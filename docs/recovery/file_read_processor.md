# Encompassing file-reader and archive receiving owner

Target `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Retained explicit-view static evidence establishes the phases below. This tranche uses ordinary first-party C++ fixtures and read-only asset parsing; it adds no native process, hook, executable patch or instruction probe.

`FileReadProcessor` owns the real containing `CommonProcessTasks`, its ordinary raw pending records and serial attachment. Its `ResourceCache`, `ArchiveMounts` receiving owner and `BackgroundCallManager` enclose `Close`. Call `Update` on their receiving thread and invoke the existing background manager's real `PostLoop` separately. Enqueue/update alone never wakes an idle worker. `Draw` delegates through the actual common graph; no renderer callback is substituted. Full engine/frame invocation remains open.

The ordinary prepared ResourceManager domain uses persistent +108=1, +173=0 and the accepted cache-aware sorter. `PendingRawReadRequests` contains the existing physical pending-pointer/cache relationship without owning a serial attachment. Both the existing exclusive `PersistentRawReadQueue` facade and the new encompassing processor use that same core. The facade retains its exclusive empty-common contract; mount records are never appended to a supplied facade's serial group. Cache Acquire/Release/ClearCache still reach the actual pending core, preserving stable reference ordering, physical cancel3/removal and selected-vs-queued cancellation. This does not implement arbitrary native incoming/sorter services.

Native `0x1404d6f10` first respects the shared in-flight mount gate, then creates an actual mount serial owner when global pending rows exist. Only otherwise does it append ordinary raw work. `ArchiveMounts` now holds that actual shared global pending domain separately from each claim-owned batch. A receiving-thread claim swaps all pending records into one batch; later queues remain global. Each row owns the genuine prepared physical metadata input and its stable `WrappedPsbReadDestination`. Body extent and exact resource/cipher identities are supplied after real path preparation outside ordinary frames. Mounted request preparation, OS handle caching and native OVERLAPPED timing are still separate.

Native mount phase0 `0x1404d6360` constructs a one-shot disk reader, calls `0x1404dbe40`/`0x1404d7850` to set +170=1 (not +108), queues each type1/wrapped index with null count/status receivers and attaches the reader to its own serial group. The source creates this genuine nested common/serial ownership, direct FIFO pending rows and real background loop. Its default +108=0 incoming/sorter slots are native empty `0x140030f20`; the persistent cache sorter is not reused. The worker physically reads current, selects following before current wrapped preparation, then uses the existing MZS, Zstandard and PSB decoders. Checked archive metadata/lookup production occurs on that worker. Native following OVERLAPPED start before current postprocessing is unimplemented.

The default type1 flag `0x14096a770` is 1. Native `0x1404d6510` enters derived texture/purge work only after an object root (7), successful optional id AND spec lookups and matching target spec. All nine supplied archive metadata roots have id and lack spec; their derived branch returns before any texture work. `PrepareIndexOnlyMount` enforces that observed object/id/no-spec domain before `ReadArchiveIndex`. Any spec presence rejects conservatively, including null and another target. The stable portable byte/document owner represents this proven empty-texture index domain; it does not implement generic MTexPSBObject layout, texture construction, purge, image/motion/font production or target dispatch.

If the worker has finished before the next parent visit, source/native graph order is: A claim mount, construct nested reader and enqueue real background child; B retire background child; C one-shot finish `0x1404d76c0` gives status 2 and retires reader; D mount phase1 registers all rows in input order via `0x1404d5760`, gives status 2 and retires mount; E ordinary raw dispatch may resume. Serial-empty is checked before onProcess, so those boundaries do not collapse. `ArchiveMounts::Unmount` removes only globally pending rows plus existing prefix registrations. It cannot touch the swapped batch. A later phase1 can restore that prefix. Pending rows belong to the receiving owner and may survive a processor which never claimed them.

The batch transfers every produced `PublishedPsbFile` into the actual `ArchiveMounts` retained owner. Its unique object identity, decoded bytes and document survive temporary-reader retirement, registration, Unmount, processor Close and processor destruction. `RetainedPsbObject` returns a const borrow bounded by the enclosing receiving owner's C++ lifetime; it does not add a resource/script root. Registration preserves the existing byte-sorted prefix/row order lookup behavior. Entries, names, output bytes, queued/in-flight/retained counts and request ids have explicit authored limits. Storage is reserved before phase publication; worker preparation produces metadata/lookup storage before registration.

Native mount destruction `0x1404d3c90` decrements the global count and destroys row strings before nested serial cleanup. Native row `0x1404d3930`, archive registration destruction `0x1404d3860` and Unmount `0x1404d7ab0` do not establish output retirement. Base PSB destructor `0x1404c95a0` and derived `0x1404d3dd0` describe cleanup, but their existence does not identify the final index owner. The source therefore never frees retained output at those phase boundaries. Receiving-owner scope destruction is authored C++ teardown, not a recovered native final-index/shutdown policy; every processor must already be closed and every borrowed output use finished. Destruction with attached processors/in-flight rows fails fast before storage drops.

`Close` preflights the actual main/common/serial owners, cancels only queued raw pointers, then fences real nested/ordinary workers before their receiving rows retire. Queued one-shot rows may be abandoned only after physical removal from that reader's pending vector. Selected work completes through the fence. Already-produced but unregistered outputs are still retained in the enclosing owner. This earlier fence is an authored forced-close safety boundary, not native arbitrary-time mount destruction fidelity. Allocation before serial publication leaves cells unassigned and permits unstarted batch restoration; native allocation-failure behavior is not claimed.

Null-status physical/decoder/index failures latch a fatal unsupported domain. They cannot become successful mounts, fake cancellation/completion or empty worker services. Owner preflight rejects ordinary retirement; destructor fails fast. A fatal discovered during an otherwise-admitted forced fence can also fail fast while nested callbacks retire. The native virtual-error/CA recovery, allocation-exhaustion recovery and complete thread/process shutdown remain open. Current-member script finalization and automatic ScriptResource wiring are not introduced.

Validation is bounded and independent: real-file fixtures exercise raw/mount phase order, no implicit wake, pending versus swapped Unmount, shared gate across two processors, unregistered output retention, pending ownership beyond processor scopes, concrete cache attachment rollback/capacity and conservative derived admission. Fail-fast fixtures arm expected termination only after assertions. First-party sanitizer checks certify source lifetimes and ordering within this supported domain; retained static phases and exact original metadata hashes provide the stated fidelity evidence. They do not certify full frames, textures, arbitrary shutdown or final native index retirement.

It writes no decoded files. Two isolated checks verify authored fail-fast destruction.
