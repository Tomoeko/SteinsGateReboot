# Scenario text search and explicit entry

`sgre-inspect search QUERY [--game-root PATH] [--language en|ja|tc|sc] [--limit N]` reads the original scenario archive without extracting files. An empty quoted query browses records. Without `--game-root`, it reads the existing `Files/config.json` under the current workspace and its configured seed source; it does not create, repair or save settings. An explicit installation reads the verified original executable's archive-seed initializer. Search is a case-sensitive UTF-8 byte substring across original text, selected translation, character and scene identity. Results own their strings and include a shell-quoted `sgre-game --jump 'SCENE.ks:LINE'` command.

The supplied `scenario_info.psb.m` SHA-256 is `85803a0a83b19387f2105db3b05a774b7561b9ce9b290a22851e8d9dfd7f566e`; `scenario_body.bin` is `b2ea22c0b906ed39c981c52ee67647341916f1aa187236fb60772233b4947d5b`. A bounded read-only metadata audit found 187 archive entries, 182 scenario resources, 797 version-one scenes and 24,795 referenced text records. All scenario resources declare English, Traditional Chinese and Simplified Chinese variants after the base Japanese variant. The reader supports this recovered version-one tuple and rejects unsupported schemas. A singleton text variant retains its base fields for every selected language, matching original `convertSceneText` without multilingual publication; 271 such records occur in the supplied scenario resources. Original markup is shown unchanged; search does not evaluate script expressions or route conditions.

Original `EnvPlayer` functions `convertSceneText`, `convLangText2` and `getText` select the language tuple and one-based text reference. Integer-headed position arrays supply their original source line at element four. Translated source line mappings are reported separately. `findSceneLine` chooses the scene before the next scene's `firstLine`; `goToLine` selects the first numeric position record whose source line is at least the requested line. The catalog uses that same first qualifying record, including repeated or decreasing recorded lines, and rejects a request with no following snapshot in the selected scene. It preserves supplied launch spelling while checking the actual ASCII-lowercase archive identity. It does not substitute a text ID, script program counter, nearby scene or invented flag state.

Each query decodes one bounded archive entry at a time through first-party archive/PSB readers. Entry, decoded byte, scene, record, compared-text, field, query, result-count and owned-result-byte limits apply. Cancellation returns only completed owned results. Jump preflight validates one actual resource; the launcher still executes the original entry hook and restore path. A valid snapshot does not prove that every earlier route side effect can be skipped or that every scene has completed runtime recovery. Complete routes, dynamic scenario expressions, rendered text fidelity and native frame comparisons remain separate acceptance work.

On macOS, explicit `sgre-inspect --gui [--game-root PATH]` uses a native scenario browser with language/search controls, text and archive-entry tables, owned details, cancellation, command copying and explicit game launch. The platform code remains inside the macOS boundary. Offscreen sanitizer checks cover actual controls, retired-document results, selection guards, queue cancellation and close/first-failure containment. Strict compilation and real-archive CLI searches pass; visible layout, clipboard and interactive launch acceptance remain open.
