# Shape-plan ownership diagnostics

This separate additive overlay requires frozen same-face owner7f028f8a. It preserves the actual face/cache/acquisition implementation and adds non-frame observations only; no original/native application service or cache capacity is inferred.

`ObserveCachedMetadata` iterates the real private Plans vector in its existing order, takes each actual shared_ptr::use_count through a const reference, and copies only property words, exact feature/coordinate keys and that observed count. It makes no extra shared metadata owner, exposes no mutable container or pointer, and preserves serialized cache/face access. Value-copy allocation may throw before publication; the cache is unchanged. `MetadataStrongReferenceCount` queries the caller's actual shared pointer without copying it and retains the ordinary live-face check.

`ObserveMetadataOwnership` creates a weak-only probe before face retirement. Its strong count and expiry read the existing metadata control block without locking it or querying metadata/face/font resources. The weak control block can remain after the data's last strong owner releases; make_shared storage may therefore remain allocated until weak probes are destroyed. No native allocator/control-block/object layout identity or native heap-free timing is claimed. Ordinary Snapshot/SharesMetadataWith/RequireFace and the direct caller count/probe acquisition still reject expired faces. A captured weak probe intentionally observes only C++ ownership after expiry.

The controlled portable comparer can compare C++ strong metadata counts to retained native intrusive plan-reference words only in the explicit serialized A,A,B,A caller-plus-cache graph, where the owner relationship agrees. The observation is labelled C++ metadata strong references. Native face intrusive references, allocator ordering/size, process-global language retirement and general concurrent count fidelity remain outside this comparison.
