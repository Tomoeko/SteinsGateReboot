# RawTex vertex interface and Metal draw

The original [RawTex packet](raw_texture_packet.md) is four XY/UV vertices in a nonindexed triangle strip. The [native program selector](motion_shader_program.md) maps this layout to VS index 4. Its DXBC is at executable file offset `0x735ec0`, 952 bytes, SHA-256 `5ff91389ad191d7238d7ee8066eac13547fcd670a195192f08b66f4b58f42b80`. Reference executable: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`.

Direct byte reflection declares an 80-byte `$Globals` buffer: column-major `modelViewProj` at offset 0, 64 bytes; `constVtxColor` at offset 64, 16 bytes. Original instructions receive XY and UV, form `(x,y,1)`, dot that vector against each of four constant registers' `.xyw`, copy register 4 to the interpolated color, and pass UV unchanged. This is a distinct interface from VS1's packed per-vertex color.

The manually authored, readable `shaders/reference/raw_texture_transform.hlsl` reproduces the entire original container under the retained compiler request. Source SHA-256 is `1dbc0fd49136b090660279262fba2aac6a4f6de23bca02cbd0d55cc159e43cd0`; compiled SHA-256 equals the original above. The request uses `main`, `vs_4_0`, both flags zero, no defines/includes and source name `recovered_shader.hlsl`. Research DLL SHA-256 is `4b074a3976399dc735484f5d43d04b519b7bdee8ac719d9ab8ed6bd4e6be0345`. A bounded console-only helper with per-process error/exception exit guards performs this compile; the compiler is never a rewrite runtime dependency. Complete-container equality establishes this request's compatibility, not the unidentified original compiler build or GPU pixel equality.

`shaders/metal/sprite_pass.metal` adds the corresponding `TransformRawTextureVertex` function. Its input is float2 XY followed by float2 UV, stride 16. The constant buffer stores the same projection registers and semantic RGBA uniform color at byte 64. The existing ordinary pixel shader consumes the verified white or tinted texture path. Pipeline caching includes the actual vertex shader index, so VS4 and VS1 cannot share incompatible input descriptors.

`SpritePassDraw::RawTextureVertices` and `RawTextureColor` preserve this separate geometry/color representation. A VS4 draw requires exactly four raw vertices, an empty ordinary vertex span, no indices, and triangle-strip topology. Submission calls Metal `drawPrimitives` with vertex count 4 and no index buffer. Ordinary VS1 draws retain their indexed path. Frame upload tracks byte offsets independently of vertex counts, so mixed 16-byte and 20-byte records stay correctly aligned. Each prepared draw receives a reusable, 256-byte aligned constant slice; later colors cannot overwrite an earlier draw's uniform. Original opaque white selects texture-attribute bit 4 and native pixel index 180; other ordinary colors select index 240 and the RGBA multiplication path.

Strict ASan/UBSan and Metal API validation pass actual offscreen Apple Silicon tests for all three mutable RGBA/BGRA/BGRX formats, nonuniform texture rows/UVs, packed ARGB tint and opacity, raw projection-register translation, exact strip coverage, independent uniform colors and mixed VS4/VS1 indexed/nonindexed draws. Unmodulated byte channels/coverage are exact; modulated UNORM comparisons permit one quantization level. Unsupported vertex counts/index buffers/topology and a library without VS4 reject. The test's bounded negative shader fixture is generated from authored source under its provided ignored output path, refuses an existing file and is removed on completion. Existing sprite and mutable Metal suites also pass against the extended renderer.

A composed fixture uses the genuine portable `RawTextureTask` with this mutable backend: native RGB restoration populates BGRA shadow bytes; task color truncation/opacity produce `0x807f3fff`; its prepared packet reaches the actual VS4 draw. Closing the task after submission expires future handles while the committed command retains its resource, and captured pixels preserve the submitted state. This connects CPU task/resource ownership to the platform draw; it does not substitute a script LayerBase/common owner.

No game process, window, input or audio API is used. Native instruction/byte proofs, source compilation identity and authored Metal pixel tests remain distinct evidence. Windows-versus-Metal pixels, full Layer/task submission, clipping/masks/alternate shaders, script RawTex registration/common ownership and frame timing remain separate acceptance checks. The [mutable backend restrictions](mutable_texture_metal.md) remain enforced.
