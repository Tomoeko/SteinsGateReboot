## Recovered frame behavior

`SubmitPreparedMotionFrame` recovers the measured ordinary one-cell quad path of original `0x140555610`. It consumes an already ordered queue; the recovered queue sorter remains a preceding operation. Scene storage owns commands, clip descriptors, member views and geometry caches through submission. The caller supplies prepared texture dimensions, transforms, viewport, initial/applied scissor and exclusive scratch streams. Batch spans are borrowed only through their output callback; retaining them across subsequent submissions is invalid.

The concrete original render owner begins with indexed triangle-strip mode 2 (`0x140559bc0` → `0x140557f20`). The frame begins with blend/filter state 0, skips hidden and zero-count ordinary commands, and preserves command order. Texture, raw filter/color, blend mode/float and packet key changes flush the previous batch before the corresponding change. Color conversion is a 32-bit right rotation by eight. Texture changes update the inverse dimensions used by UV arithmetic. Equal blend parameters, including opposite signed zero, suppress redundant state changes.

A changed non-null clip group prepares its child/parent mask plan. Non-null-to-non-null transitions do not finish the prior mask first; a non-null-to-null transition does. Automatic region clipping combines the eligible same-group queue run with the recovered parent-chain bounds, transforms the result and applies floor(minimum)-2 / ceil(maximum)+2 before intersecting the initial physical scissor. Unavailable or reversed group bounds retain the original fallback.

Mask candidates retain their visit order and texture changes. They ignore ordinary geometry-count exclusion and use four opaque white colors from `0x140655b98` with key/flags 4. Configure/Begin/End/Resolve flush pending mask packets at their native boundaries. Resolve recomputes the effective scissor and invalidates the texture-slot cache, forcing the next visible ordinary command to select its texture even when it is the same slot.

Individual clips cache their borrowed rectangle identity rather than comparing rectangle values. A changed identity transforms/intersects the rectangle with the initial scissor and may flush/reissue equal raw state; the rounded scissor cache can still suppress the device rectangle. Invalid individual bounds suppress drawing. A valid individual/group pair with an invalid intersection suppresses ordinary drawing, while mask candidate append still occurs under the previous scissor. This asymmetry is retained rather than replaced by a generic clipping rule. If one rectangle is invalid, scissor selection can fall back to the valid other rectangle, independently of the individual-validity draw gate.

Special blend 0x10d uses the recovered paired/separate-axis pass planner. Each pass flushes, selects its native parameter, measures the command's lazy geometry bounds, flushes again, sets blend bounds and appends the ordinary colored packet. The surrounding frame retains the source blend cache, finishes any final active mask, restores mask control to operation 0/minimum 1/maximum 0, restores the initial scissor and ends.

The typed output exposes these state requests, candidate visits and complete borrowed batch submissions. Mask phase records route to `PrepareMotionStencilTransition` at a stencil backend; their descriptor policy is independently validated. The frame emitter itself makes no OS/GPU call. Source owners and views must remain stable during callbacks, and scratch streams must fit the largest coalesced packet. It performs no decoding or allocation. Native enum/format/shape variants outside its explicit scope reject; prepared field, graph, candidate and capacity checks run before Begin where possible. The global 1,048,576-work budget bounds traversal/lookup/pass work; streaming-capacity exhaustion or a sink diagnostic can abort a begun frame. Such C++ errors must be caught before an OS/C ABI boundary, and a platform owner must handle partial frame effects.
