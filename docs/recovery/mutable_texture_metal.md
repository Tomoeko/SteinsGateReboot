# Mutable textures on Metal

`SpritePassRenderer::CreateMutableTextureBackend` connects the recovered exclusive [mutable texture owner](mutable_texture_owner.md) to the renderer's actual Metal device and command queue. `MutableTextureBinding(0, MutableTextureStage::Pixel)` returns a borrowed, generation-checked draw handle after `owner.Bind(0, Pixel)`. The backend must outlive the portable owner. Renderer-first shutdown expires the guarded registration context; subsequent create/upload/bind operations reject, while later owner destruction remains safe.

The supported description is a default-usage, sampled, non-multisampled texture with one mip and original format 28 (RGBA8), 87 (BGRA8) or 88 (BGRX8). Native format metadata remains unchanged. The renderer compares recovered shader interpretation rather than treating these byte textures as compressed BC7 resources. Format 28 uses `RGBA8Unorm`; formats 87/88 use `BGRA8Unorm`. BGRX's sampled view forces alpha to one, applying the [DXGI format's unused channel](https://learn.microsoft.com/en-us/windows/win32/api/dxgiformat/ne-dxgiformat-dxgi_format) and the documented [missing-alpha texture default](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-to-type). No source bytes are swizzled or rewritten for this view.

The texture and sampled view belong to the mutable owner; its sampler is also an exclusive backend object. The renderer registry holds weak ARC references to the view/sampler. It releases the borrowed identity and advances its generation when the resource retires. Previously submitted Metal command buffers retain their encoded resources until completion, so owner release invalidates future submissions without invalidating an earlier one. The ordinary public `ReleaseTexture` operation rejects mutable handles; the owner performs their release.

Three reusable transfer buffers are allocated with each texture. Upload validates the caller's row pitch and complete byte range, copies rows into a free buffer and commits a blit on the same queue used for drawing. Shared-buffer rows are aligned to 256 bytes. Earlier draws finish before a later upload changes their sampled texture; the next draw sees the new bytes. The requested texture bytes and all three transfer buffers count against the renderer's aggregate texture budget. The portable CPU shadow has its separate allocation limit. These bounds count requested storage; they are not a measurement of hidden driver allocation overhead.

Uploads allocate no new byte storage and do not wait for the GPU. They reject a full transfer queue or a failed prior upload with a contextual error. Explicit capture remains a blocking validation operation outside ordinary frames. Native blank allocation content is unverified; the tests initialize every sampled texel and make no blank-pixel claim.

The renderer consumes the owner's cached sampler rather than replacing it with the ordinary pipeline sampler. Original min/mag/mip filter bits and clamp/repeat/mirror addresses map to Metal's corresponding sampler fields. Single-mip LOD clamps stay zero and anisotropic filtering stays disabled. Therefore a filter-only update retains the current sampler; a subsequent address invalidation recreates it with the latest desired filtering. The currently translated ordinary shader consumes only pixel slot zero. Other slots/stages explicitly reject, even though the portable owner preserves the broader measured native state behavior.

Headless Apple Silicon validation, with strict ASan/UBSan and Metal API validation enabled, verifies all three format channel orders, BGRX opaque alpha, nonuniform padded source rows, queued updates preserving an earlier draw, actual nearest/linear/repeat sampling, native filter-cache behavior, owner release after submission, stale handles, generation reuse, foreign renderer rejection, byte/count limits and renderer-first teardown. The existing sprite suite also passes, including ordinary shader operations, twelve blend modes, sampler behavior, immutable texture sharing and resource bounds. No AppKit window, original-game process, input or audio API is involved.

The metadata and ordering source remains the unchanged original executable documented by the portable owner. These Metal tests compare the authored platform output against independent expected pixels. They do not compare this backend against a Windows GPU capture or establish bit-identical cross-API filtering. Dynamic/staging/render-target/depth descriptions, hardware maps, companion copies, extra formats/mips/samples and additional shader slots/stages remain unsupported. The original RawTex XY/UV layout, uniform-color shader and nonindexed strip submission remain a separate integration acceptance check; this backend currently feeds the measured ordinary sprite renderer.
