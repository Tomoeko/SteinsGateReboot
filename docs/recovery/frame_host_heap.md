# Actual per-frame host heap producer

`FrameHostHeap` owns real temporary host pages and actual suballocation spans. It recovers the host portion of original `MPerFrameGPUHeap`/paged vertex pool from `54bc50/54bd10`, Begin `54c6e0→54bec0→54bfa0`, End `54c6f0→54c040` and cached used-byte query `54c710→54c730→54c390`. Its explicit positive physical-frame count is a containing backend descriptor input, not an invented clock, OS event or GPU owner. Native Display obtains that count from the actual swapchain descriptor (`4c47c2/4c47c5`). Whole pool construction and automatic graphics-hook registration remain unaccepted.

The initialized native heap starts at counter 0 (`54c110`); Begin increments uint64 with defined wrap, selects counter modulo physical count, clears the selected resource-entry byte and retires that physical frame's host pages. Actual allocation wrapper `54c6c0` replaces alignment 0 with16. Each existing page is scanned from list head, its used offset is rounded relative to that page, and enough remaining capacity is required before choosing it. A new page rounds requested/minimum 65536 up to 65536-byte units and is prepended. Used high-water includes alignment padding; capacity and used bytes are distinct. Allocations have stable page identities; shifting page metadata does not move their storage.

A tiny new original-byte discriminator confirms initialized frame 0 allocation before Begin: count 0 owns a nonnull 65536-capacity page with used 0, count 1 reuses offset 0/used 1, and the next count 0 selects offset 16/used 16. End sets the resource-entry byte 1. Another allocation still succeeds, preserving that byte; it is not an allocator readiness gate. Begin of the next physical frame allocates independent storage and later recycling frees actual host pages/list nodes. There is no claim that an uninitialized native heap or whole constructor has been supplied by this module.

The portable owner provides an admitted domain of 1..64 physical frames, power-of-two relative alignment up to 65536, and explicit host budgets capped at 64 MiB/1024 pages (defaults 16 MiB/256 pages). Unsupported arithmetic, capacity or identity exhaustion throws before allocation/high-water mutation. Actual host allocation failure uses the authored exception model; native failed-allocation behavior is unaccepted. Original malloc addresses, uninitialized/padding contents and GPU transfer bytes are not a fidelity claim. Authored page storage is initialized; callers explicitly write their accepted data spans.

`FrameHostAllocation::Bytes` checks a weak live heap receiver and actual never-reused page identity, rejecting close, destruction and physical-frame recycling without retaining the page. A returned span still borrows: every writer must finish before its actual containing worker/draw fence allows Begin, Close or destruction to retire storage. The allocator and handle lookup use a real mutex; Begin/End/Close operate on the containing owner thread. No worker fence, GPU pointer or default service is installed. Cached used bytes change only when the actual query is invoked.

The observed resource-entry byte remains named by its physical location. Begin 0/End 1 are recovered writes; the original16-byte GPU resource entry's full registration, generation/pointer binding and consumer meaning remain open. This byte does not assert GPU readiness or upload completion.
