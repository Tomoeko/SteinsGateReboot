# TextRender vector glyph cache and draw lookup

Target: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Addresses are executable virtual addresses in the exact read-only PE view. No original bytes or analysis metadata changed.

Each TextRenderVectorFont interface (`0x140087830`) owns a nested cache rooted at interface `+0x20`. Exact assembly identifies outer size keys as unsigned 32-bit at node `+0x20` (`0x140087c60`, unsigned comparison), middle edge-width keys as signed 32-bit at `+0x20` (`0x140087a30`, signed comparison), and glyph IDs as unsigned 32-bit at leaf `+0x1c` (`0x140087b60`). Leaf payloads at `+0x20` contain six signed words: atlas X/Y, glyph left bearing, top translation, width and height.

Glyph-run preparation (`0x140087f30`) walks the actual shaped run in order. An empty run does not construct buckets. For each nonempty run it creates the size/edge buckets and prepares only absent glyph IDs. Repeated IDs reuse the same entry. On each miss it synchronizes the borrowed vector core from the interface word, calls actual glyph raster preparation `0x140089110`, and commits the returned six words. An all-zero result is still an entry. Empty glyphs or failed atlas allocation are not retried on later preparation of that same key. The portable `VectorGlyphCache` requires an actual glyph-preparation callback on a miss; it does not substitute a synthetic renderer.

Draw lookup (`0x140088100`) creates the requested size/edge buckets even for an empty run. It never prepares missing glyphs. It draws only existing records with both signed width and height greater than zero. The submitted position preserves separate float operations: X is origin X plus shaped glyph X; Y is unsigned interface size converted to float, then origin Y, then shaped glyph Y. It forwards the stored region and unchanged color to `0x140086a40`. `PrepareDrawRun` writes these actual lookup decisions into caller-owned capacity and preserves run order. A prepared bucket requires no draw-time allocation; ordinary rendering should prepare every needed bucket beforehand. Final rectangle projection and backend submission remain separate recovery operations.

Cache records do not own atlas storage or texture references. The interface destructor `0x140087d90` frees the three map levels through `0x140087790`, `0x140087660` and `0x140087730`, followed by its sentinel and optional wrapper storage. It does not release its borrowed vector core, text context or per-record GPU objects. Actual atlas allocation `0x1400369c0` uses one texture owned by the text context at `+0x428`; it does not automatically create additional pages when that surface fills. That owner/texture lifetime must cover every retained cache record. The independent full-font raster census used caller-controlled surfaces and does not establish native multi-page growth.

## Validation and scope

A prepared CPU oracle executes unchanged interface construction, original nested map creation/rebalancing/lookup, run preparation, draw lookup and populated destruction for 250 owners and 4,000 operations. It includes unsigned boundary sizes/IDs, negative and boundary signed edge widths, repeated/empty/unprepared runs, cached all-zero records, positive-extent suppression, float baseline order and value-only cleanup. All 127,533 projected state, preparation-call, cached-record and draw-position/color words match. Trace SHA-256: `2763fa965107e0fe5bd0d3af33fa4e7d241e89e6d51727caba12eb8bb49e03b2`; 2,193,405 original instructions execute. The actual raster result at `0x140089110`, final command emission at `0x140086a40`, caller heap and FT size-driver dispatch are explicit bounded observers/preparation boundaries. This proves cache and routing behavior, not stroke rasterization, shaping, atlas upload or final pixels.

Strict-warning ASan/UBSan fixtures also cover bounded runs/entries/buckets, no callback on cache hits, failed preparation retaining prior state without committing a result, callback mutation guards, output capacity and nonfinite-position safety rejection. Limits are portable input/allocation safeguards, not inferred native resource limits.

Full native atlas/context texture ownership, joining real unstroked CFF raster output to these records, final rectangle projection and GPU glyph submission remain open. Edge width is retained exactly as a cache key; unsupported stroked glyph pixels are not replaced by filled glyphs. No original game launch or screen/audio capture was required.
