# Character processing and table lookup

The reference is `sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`.

The native table reader at RVA `0x25CA70` selects `hash & (capacity - 1)` and follows each node's `Next` pointer. Its complete 233-byte body was independently checked against the executable. A separate original-instruction witness passes four cases, 200 reads and 71 physical-table snapshots, including real weak-value lifetime. The rewrite now uses the existing table collision chains instead of scanning every physical slot. Hashing, key equality, insertion, displacement, deletion, growth, enumeration, class/instance layout and garbage collection retain their existing implementations. Lookup rejects invalid capacity, out-of-range links and cycles.

Mesh packet validation previously repeated a full ancestry check for every selected vertex cell. A synchronous internal batch now checks the owning phase once before checking every cell's identity, serials and geometry span. Public borrowed access still validates the complete phase. No callback or mutation may intervene within that internal batch; no readiness result survives it. Geometry calculations, traversal, ownership, timing and draw order are unchanged.

Independent nested-task comparison preserves all 8,200 serialized output words across six preparations, including source retirement and rebuilding. Actual registered-asset callbacks fall from 2,412 to 1,008. Existing native geometry vectors, stale-owner/span corruption checks and 22 connected sanitizer suites pass. The VM fixture has 57 groups, including collisions, deletion, typed keys, weak values, context roots and cloned tables after source retirement. An isolated 100-miss sparse-table comparison performs 100 key comparisons instead of 409,600; this is a work count, not an application speedup.

Two 180-second observations use the same direct-game entry and timed input, Release optimization, Metal validation and a hidden, inactive window with offline discarded audio. In the fixed 60–85 second character-entry window, mean root Update plus Draw duration falls from 22.87 ms to 14.44 ms, and draw cadence rises from 39.7 to 57.7 Hz. Both retained 60-second images contain the same character; dialogue reveal and exact animation progression differ. These measurements establish a bounded observed improvement, not a deterministic replay, GPU timing, whole-game performance guarantee or native Windows fidelity. Other models and cold loading still require separate measured coverage.
