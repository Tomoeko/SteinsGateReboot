## Actual Metal backpressure

The renderer has three upload slots. When all remain submitted, it now waits for the oldest exact command buffer's completion signal rather than rejecting the next frame. Each fixed slot owns one OS semaphore; an OS-only completion handler signals it, and reuse consumes exactly that prior signal before overwriting buffers. Same-owner command/submission/status checks, a30-second diagnostic deadline and actual NSError propagation guard failure. No wait changes game clocks or synthesizes frame progress.

A real Metal shared-event gate deliberately blocks three uploads, then admits the fourth through genuine completion. Both Submit→live-encoder and live-encoder→Submit directions preserve four independently captured colors; unsubmitted Abort/reuse also passes. This validates buffer lifetime and bounded backpressure, not native game frame timing or performance.

The focused reader previously validated every registered conversion before sampling, so the missing table row stopped both startup modes even with no key pressed. Hidden observations did not reach that focus-only check.

Microsoft's [keyboard input table](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-keyboard-input) distinguishes dedicated Insert from keypad0. USB Help shares the Apple position; this establishes a compatibility mapping, not a connected-device claim.
