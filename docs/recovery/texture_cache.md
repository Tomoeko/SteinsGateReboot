## Identity and lifetime

Texture import `0x140547ef0` stores the original PSB value pair and checks the shared vector at `0x140a97430`–`0x140a97438`. Each 32-byte entry contains a GPU pointer, document pointer, serialized value pointer, and signed reference count. Equality helper `0x1404c98a0` compares both PSB identity fields. A cache hit increments the first matching entry's count without uploading again. Matching pixel chunks, contents, filenames, or source names do not establish this identity.

The portable parser preserves each `PsbValue.SerializedOffset`, including repeated references to one serialized atom. `ImageTexture.SerializedValueOffset` carries the texture value's identity independently of `PixelRange`. `TextureCache` combines that offset with the loaded document owner's nonzero `DocumentInstance`. The cache-scoped allocator and [loaded motion owners](motion_assets.md) preserve distinct live document identities without relying on pointer width or recycling; synthetic values without recorded offsets are rejected by preparation.

Each cache record owns one uploaded backend texture and its logical references. A miss decodes through the first-party image decoder and invokes the platform upload service outside ordinary frames. Services outlive the cache; native resource adapters separately retain their required PSB script owners and immutable backing. `TryAcquire`, metadata access, filtering changes, reference release, and registration enumeration allocate no storage. Preparation limits bound entry count, a decoded texture, and aggregate upload bytes. Generation checks reject stale or foreign authored handles rather than reproducing native invalid-pointer behavior.

`0x140548880` normally releases the shared GPU owner through `0x14054b0c0`. That routine searches by physical GPU pointer, decrements the count, destroys/frees the GPU object when the count reaches zero, then compacts the surviving registration vector. Intermediate release preserves the object and its position. `TextureCache` preserves this order, including removal of its checked bookkeeping after a reported platform cleanup failure. Explicit `Close` attempts all remaining owners before platform services expire; its safety cleanup order has no full native-shutdown fidelity claim.

## Sampling and motion wrappers

`0x14054b1f0` stores the wrapper's filter pair and updates the shared physical texture through `0x1404f8dc0`. The shared cache exposes the physical texture's latest minification/magnification values. Raw filter values remain explicit; the current ordinary draw classifier supports only its separately recovered pairs. Storing a setting does not prove unsupported D3D sampler or Metal behavior.

Motion import callback `0x14052b000` creates a separate 72-byte native texture wrapper, then registers it in the motion layer's slot vector through `0x14052bb40`. The constructor starts with eight empty slots; registration selects the first empty slot and doubles a full vector. `0x14052af40` distinguishes borrowed wrapper entries from owned ones before disposal. Owned/borrowed wrapper slots and their measured sampler propagation are implemented separately in [motion_textures.md](motion_textures.md). Dynamic overrides, project/source ownership, two motion managers per script Layer, cross-target device sharing, and complete scene submission remain separate integration work. The shared cache is not a replacement Layer implementation.
