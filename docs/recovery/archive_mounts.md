# Archive registration and resource paths

Target `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Preferred-image VAs below were recovered read-only from the game Binary Ninja view.

`System.mountArchive` (`0x140285ba0`) accepts prefix, info identity, body identity, and an optional boolean. The ordinary three-string path queues registration through `0x1404d5e30`, pushes integer zero, and returns one VM value. Processing at `0x1404d6360` has dispatch and completion phases; loaded indices are registered through `0x1404d5760`. Prefixes are stored unchanged in a byte-sorted map, with multiple archives retained in registration order per prefix. The observed false boolean path is implemented. The alternate read-mode flag remains an explicit unsupported error until its body-read semantics are recovered.

Request normalization at `0x1404d6230` replaces every backslash with slash and repeatedly collapses `//`. It does not change case or resolve dot segments. Request lookup at `0x1404d70f0` walks the prefix map and its archive vectors, matches exact prefix bytes with a nonempty remaining request, and applies the archive’s expire-suffix list. For each suffix it finds the first occurrence and strips only when that occurrence reaches the request end; it does not assume a last-occurrence or generic extension rule. Exact original entry lookup selects the body range. Prefix order is not replaced with an invented longest-prefix policy.

The portable mount service accepts already validated archive indices from host preparation. It owns compact metadata and maps, reserves registration capacity when mounts are queued, and exposes exact source/body identities with the checked entry range. Preparing/read/decode work occurs before registration; the ordinary-frame completion phase performs no filesystem operation or index decoding. Synthetic fixtures validate normalization, preserved case/dot segments, delayed registration, duplicate-prefix source order, suffix corner cases, and removal of active/pending registrations.

The optional local startup fixture prepares all nine original indices, executes the supplied init mount call, and resolves the actual `config/revision.psb.m` entry. Resource-object construction and typed PSB access now consume original config documents; complete startup still stops at explicit unrecovered behavior. Queue timing uses already completed host preparation and has not been certified against full native worker timing. Alternate read modes, cancellation priorities, loose-file fallback, archive version diagnostics, exact threaded scheduling, and full resource/job lifetime still require recovery. The current owned background reader/publication boundary is documented in [resource_vm.md](resource_vm.md).
