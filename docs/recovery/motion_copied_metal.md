# Metal copied-region resources

The offscreen Metal mutable backend implements the narrow `MotionCopiedTargetBackend` and `MotionRegionCopyBackend` capabilities on the same concrete backend/device identity as its exclusive `MutableTextureOwner` resources. Preparation checks those capabilities once. This adds real copied-target resources and queue submission to the native-backed [region owner](motion_copied_region_owner.md); it does not substitute the immutable asset cache for a writable target.

Original kind 5 uses default usage, shader-resource and render-target binds, one mip/sample and the current rendering target's original format. The backend supports original RGBA8 (28), BGRA8 (87) and BGRX8 (88) descriptions through the established format mapping, with Metal private shader-read/render-target textures. A distinct scoped render-target-view owner retains the actual physical texture independently; closing the copied owner first retires the `MTexture` abstraction/borrowed shader handle and then its render-target view. CPU upload buffers are absent for these targets. They cannot be CPU-mapped or uploaded through the shadow path.

The current offscreen renderer's target is RGBA8, so region copying requires original format 28. The backend checks matching source/destination formats, nonnegative integer source coordinates, source bounds and destination capacity. It enqueues a Metal blit into destination origin zero on the renderer's existing command queue. Earlier drawing, copied-region blits and later sampling therefore execute in submission order without a blocking wait. Three preallocated copy-command records per backend bound pending copies across target replacements; a full queue or previously failed command reports an explicit error. Allocation, copied-target resizing and shader preparation remain outside ordinary stable frames. Capture readback and waits occur only in validation.

The strict Apple-Clang ASan/UBSan tests run with Metal API validation and no app/window/audio creation. A nonuniform 4-by-4 source tests the exact source box and 2-by-2 destination. A half-size follow-up retains the same texture, overwrites only one pixel, and verifies the other previously copied pixels remain. These two captures compare 128 exact RGBA channels. The tests also cover copy-to-draw ordering without intermediate waits, close after committed submission, future stale-handle rejection, wrong backend/kind/format, rectangle bounds, unsupported CPU upload and cleanup when the renderer closes before its copied owner. Existing sprite, mutable texture and RawTex paths are regression checked against the same extended renderer.

This is a physical GPU-copy/lifetime and independent expected-pixel proof on Apple Silicon. Native CPU/device-request traces provide construction, ordering and rectangle provenance. It is not a Windows GPU differential or whole-frame/shader parity claim. Ordinary sampling of the copied resource is exercised through the existing measured color path. The [PS1205 pass](motion_copied_additive_metal.md) separately validates actual copied pixel slot 2, its affine and additive blend coupling. Auxiliary slot 1, remaining alternate shaders, full frame state stack and copied-target rendering remain separate gates. Blank native GPU allocation contents remain unknown, and no test asserts their pixel values. Dynamic/staging/depth/multisample/multi-mip resources remain outside this backend's supported domain.
