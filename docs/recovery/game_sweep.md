# Automated scenario checks

`python3 tools/game_sweep.py` builds a queue from the entire original scenario archive through `sgre-inspect test-plan`. The supplied archive contains 187 entries, 797 scenes and 39,440 snapshot records. The original first-following-line resolver can directly address 30,548 records; repeated/decreasing lines and shared scene boundaries leave 8,892 records reachable only through sequential progression. The inventory preserves all records. The queue targets each scene's final addressable snapshot and prioritizes the largest connected scenario family without resource-name rules.

The runner starts bounded hidden, inactive, silent 1280×720 processes with isolated saves. Original sequential seek restores the nearest retained predecessor and executes the original commands, movie confirmation and supported resource-defined phone input. It never substitutes route flags or claims unknown choices were exercised. Complete original save-state hashes and storage/label/line/point/record receipts identify observed snapshots. Seeking then releases skip and the runner briefly advances ordinary frames using owned input samples. No global keyboard, pointer, other-application audio or hardware output is used. Test captures do not publish into the shared checkpoint cache or automatically read back screenshots.

`Files/testing/game-sweep/plan.json` retains inventory and jump intervals. `summary.json` groups exact diagnostic failures, lists observed transitions and unresolved destinations, and retains coverage denominators and pending checks. Only receipts matching the complete original record tuple count toward inventory coverage. Each case has a reproducible launch command, original state ancestry, compressed log and runtime/retirement result. Identical inputs/settings resume completed cases; changed executable, linked core, shaders, inspected resources, configuration or runner require another output directory. `--limit N` bounds each invocation, `--target SCENE.ks:LINE` selects specific original coordinates, `--timeout SECONDS` bounds each child, `--post-seconds SECONDS` changes the ordinary-frame probe, and `--retry-failures` reruns unresolved checks. By default, a runtime error stops the batch at its first reproducible cause; `--keep-going` continues collecting cases. Retirement-only failures remain visible without blocking useful scene discovery. An exclusive suite lease prevents overlapping runners. Checkpoints and user save/configuration namespaces are checked for changes. Existing inputs are never removed.

Use `--replay PATH/TO/result.json` for one retained failure, or `--retry-from OLD_SUITE --output NEW_SUITE` to check earlier failures after rebuilding. These select the original new-game producer or the exact retained predecessor SHA-256 and use fresh isolated saves. Missing predecessors and changed original resource identities reject explicitly. Generated reproduction commands use this replay path rather than reusing a previous run's save directory.

Use `--cold --target SCENE.ks:LINE --timeout SECONDS` to test the complete original path from new game. This deliberately avoids checkpoint shortcuts so restoring a recent checkpoint cannot mask a resource lifetime bug in earlier traversal.

Exit status 0 means the selected checks completed without detected faults, 1 means a failed/crashed/incomplete check, and 2 means genuine route input blocked a check. A missing target receipt, lost protocol event, caught script exception, timeout or signal cannot pass. Runtime arrival and teardown faults are recorded separately: an authentic snapshot plus ordinary frames does not excuse a failing retirement path. The current bounded teardown can reject rootless script finalization; this remains a recovery failure, not a suppressed baseline.

Observed transitions do not verify which conditional predicate won when exits share a destination. Structural terminal controls are not counted as recovered endings. Skip-path execution and a short ordinary-frame probe do not establish every route-state combination, menus, timing, visuals, audio, save/load equivalence or native fidelity. Those remain explicit acceptance work. Independent tests exercise inverse jump intervals, caught-error classification, exact arrival, blocked choices, real pipe ownership, signals/timeouts, JSON escaping and failed evidence output; actual-game observations qualify the connected path separately.

Hidden original-menu checks can reuse the bounded headless stdin input queue: `r` confirms, `x` cancels, `u`/`d`/`<`/`>` navigate and `e` supplies Escape to the original input mapping. Keys pass through the actual InputHub with separate press/release frames. These commands generate no host events or F1–F12 shortcuts. Retain the input schedule and menu/frame evidence; a completed input sequence alone is not menu acceptance.

Route blocking and retirement are independent report outcomes. A later shutdown error does not replace `blocked`; `retirement_failed` remains true and the command still fails for that cleanup error. `runtime_reached` requires the exact requested snapshot, arrival, normal post-arrival frames and a completed observation boundary. Attempted and pending scene counts are separate from completed and remaining checks. A recorded keypad/choice block never counts as target completion.
