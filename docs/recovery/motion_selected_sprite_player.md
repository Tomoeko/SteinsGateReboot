## Ownership and caller sequence

The caller owns commands, manager registrations, root/render controls, immutable raw resource/timeline, matching prepared frames/curves/source registry, registered textures, manager ID pool and draw context. They outlive the selected player. The player exclusively owns selected nodes, per-node source caches, local evaluation caches, four-point geometry and lazy bounds, persistent rows and the current pointer queue. Destruction retires selected nodes before row storage.

1. Actual `SetCharacter`/`Play` selection precedes `Rebuild`. The supplied character and timeline must belong to the actual selected registration. Rebuild first retires the old selected IDs/geometry and then constructs new nodes; same-sized numeric rows persist. This API does not stand in for the full native `0x14051bd50` Play producer or delayed-selection installation.
2. `Update` receives actual manager delta, advances real clock/tag/priority/local cursors, binds the selected current source pair, queues layer actions, conditionally composes root/layers/geometry, publishes rows and synchronously delivers events. Geometry dirty acknowledgement occurs only after this whole admitted geometry phase succeeds. A failed composition, publication or detached delivery invalidates published rows.
3. `Draw` appends actual published row identities to the supplied context. Until successful flush or explicit clear, the caller keeps row owners, resource/texture owners and row values unchanged. Player mutation/rebuild/retirement rejects during that context borrow. Destruction with pending borrowed rows is a programmer lifetime error.
4. `MotionSpriteDrawContext::Flush` sorts the actual references and supplies populated commands to `SubmitPreparedMotionFrame`. The actual driver supplies viewport, matrices, target bounds, initial/applied scissor, texture dimensions, exclusive reusable scratch and an output sink. Event and batch spans borrow scratch/ordered rows only through that synchronous sink call; the sink must consume or copy them before returning. A failed sink retains the queue and its owner borrows for retry/clear. No GPU submission or texture pin is inferred.

The update owner caches borrowed tag metadata across rebuilds. This bounded owner records nonowning project IDs for all prepared registrations and requires them all to remain live; this is a lifetime restriction, not an additional manager retain. Frame strings and queued events still borrow their real resource/prepared-frame backing through delivery. A listener must preserve that backing throughout its call. The rejection fixture deliberately retains an external synthetic resource owner; it does not prove native callback-unregister safety. Native resource/event pins remain unresolved.
