## Borrows, release and remaining boundary

The source manager, looper clock, seed span and immutable alias/raw resource owners outlive the runtime/tasks. The first-party script resource alias accessor returns a borrowed asset span without a scoped or permanent extra PSB/model retain. Cached preparation owns decoded frame strings/indexes; raw timeline/tag/source/icon/alias data remain registration borrows. Prepared registration IDs and source order are checked before reuse/submission; new registrations require a real Force installation. Removed prepared registrations require task/runtime retirement and reconstruction; Force does not revive expired borrows. Final unregister can invalidate all raw backing, including queued event strings. Callback unregister while using borrowed event views remains unsupported; no copied queue or speculative native pin is added.

The real context borrows player row/geometry storage through successful Flush or explicit Clear. Controls, selection and release reject outstanding borrows. New `ParallelTaskCallbacks::CanRelease` is an **authored observational lifetime guard**, not a native vtable callback or pin. Clear preflights every linked owner before cleanup; status-2 retirement preflights all owners before unlink; Layer task cleanup preflights all concrete groups. Missing preflight callbacks preserve the existing unborrowed protocol. Failed preflight retains all actual ownership for retry. Callbacks cannot mutate/reenter their preflight; arbitrary new drawing during cleanup is outside this scope. Destruction of an active or borrowed owner fails fast. This does not claim whole DriverClose quiescence or automatic propagation through unrelated composite adapters.

Tasks/IDs/context borrows retire before runtime random/preparation storage, then the external manager/PSB/cache owner can retire. Actor failure invalidates publication; the containing task survives until valid cleanup. Task groups outlive every weak task view, and returned const views require stable actual group ownership. Task transfer, clone/modifier-map entries, async scheduling, delayed installation inside Update, JOIN/division, kind3, UID/mesh/stencil/clip families, dynamic projection invalidation and VM finalizer/listener registration remain closed. Projection setup precedes player construction.

The next containing boundary is the real application clock/seed provider, per-Layer runtime attachment/release and SQMotion borrowed listener/wrapper policy. Those services must exist before registering Motion in the VM. The existing source geometry gate also remains intact: original serialized nonempty icon meshes require a proved native binding/geometry branch, even when the layer meshTransform is zero. This owner is not a substitute source family, bootstrap, clone, renderer, empty Motion class or complete application loop.
