# Resource ownership and retention

Target `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Addresses below are preferred-image VAs recovered read-only in the exact game Binary Ninja view.

The resource manager owns distinct name-keyed loading, active, and retained maps. `0x140248dc0` acquires references, coalesces pending requests, and revives a cached entry into active ownership. `0x140249510` advances completed loads in map order: referenced entries become active, unreferenced successes become cached, and unreferenced failures are destroyed. Completion is a separate phase from worker I/O. `0x140249c60` and `0x14024c630` release references; the last active reference enters the cache, while an abandoned pending request updates its discardable flag and processor wakeup.

This is a two-group retention queue, rather than an assumed general LRU. `0x140248f80` inserts before the first entry with an equal discardable byte. Re-prefetching a cached entry at `0x1402497a0` clears that byte and promotes the entry to the front. `0x140248b60` evicts the tail while cached plus active charge exceeds the configured limit. Referenced active resources remain owned even above that soft limit. The native routine returns immediately when cached charge is zero, including zero-sized retained entries.

`System.setResourceCacheLimitSize` at `0x140289570` reaches the manager’s 32-bit field through folded setter `0x140052ce0`; it only stores the limit and does not synchronously trim. Adjacent folded functions belong to unrelated classes and cannot identify manager layout by proximity. `0x140284860` retrieves the limit, `0x140248b20` produces the six state words, and `0x140248220` clears retained data while preserving referenced active owners. The script state table exposes `cacheLimitSize`, `totalActiveSize`, `totalCacheSize`, `loadingEntryNum`, `activeEntryNum`, and `cacheEntryNum` as signed 32-bit payloads. The registered Sqrat setter initializes zero, ignores a failed native integer conversion, and forwards the resulting value; this particular behavior is kept explicit instead of changing general VM numeric errors.

The portable cache owns byte buffers, immutable lookup identities, bounded accounting, checked references, and generation handles. Startup parsing acquires those owned raw buffers before constructing independently owned VM prototypes. Backing pins add checked active references, keep the cache implementation alive beyond its facade when needed, and release through the recovered retention policy on the owner thread. Each returned native PSBObject can obtain its own pin while nested values retain their owner. Preallocated slot/order capacity avoids allocation during retained-state transitions. Parsing, worker completion, resource registration, and VM construction remain outside ordinary frames. System limit/state/clear callbacks act on that actual owner.
