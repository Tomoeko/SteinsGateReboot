# Blob-backed font face and table references

`BlobFontFace` recovers the resident-byte face preparation path: `0x1403a76e0` creates a readonly source blob, then `0x1403f2690` references and admits it through the whole-font sanitizer `0x1403f1e00`. The original constructor owns a 16-byte closure containing that parent blob and a uint32 face index, installs the genuine table callback `0x1403f1550` and closure destructor `0x1403f1530`, and creates a 120-byte face. This stage recovers those successful-allocation ownership and table-view semantics, without exposing effective cache readiness.

Logical executable input is `STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Binary Ninja analyses are read-only and explicitly target `candidate:view:1:UEU`. Addresses are executable virtual addresses.

The public constructor consumes the same `shared_ptr<const vector<uint8_t>>` resource-pin type used by `VectorFont`. Clean parent bytes retain that actual pin without duplication. Repair owns a replacement vector and drops its reference to the original pin. Rejection and absence publish an empty parent. The selected face index remains uint32; the primitive does not conflate it with shaping mode. A child `FontFaceTableBlob` retains the admitted parent bytes, so its view remains valid after the face is destroyed. Its last release retires the pin. Shared ownership models the actual `0x1403f6260` parent reference and child destructor `0x1403f6060 -> 0x1403f6350`; it introduces no fabricated provider callback.

Whole-font admission follows `0x1403f2570`, `0x1403f24f0` and `0x1403f1bf0`:

- Recognized SFNT directory signatures `0x00010000`, `OTTO`, `true` and `typ1` require the 12-byte header and a bounded count of 16-byte directory records. It does not validate table payload offsets, tags, checksums, uniqueness or ordering at this phase.
- `ttcf` requires eight bytes. Major versions 1/2 visit the uint32 face count and uint32 offsets; other versions admit the bounded header and subsequently select no directory. Zero face offsets are skipped. A relative face offset beyond the whole blob fails before repair, while a reachable but invalid directory may have its offset erased. The nested directory validator does not impose a guessed nested outline signature.
- Other signatures admit a bounded four-byte signature and select no table directory. This is blob admission, not a claim that the font decoder supports that outline.
- Denial-first COW retry, the native 32-edit ceiling and zero-new-edits verification are preserved. Initially immutable input denies needed repair. Invalidity releases the acquired blob and replaces it with the original empty blob.

`ReferenceTable(tag)` recovers the original callback. Tag 0 references the whole parent without freezing it. A nonzero tag freezes the parent before directory selection. Standalone directory selection ignores the requested face index; collection selection uses the closure index and skips missing/zero selected offsets (`0x1403f19c0`). Table offset/length fields remain absolute to the whole parent, including collection faces.

Directory lookup (`0x1403f1810`) uses a first-match linear scan below 64 records. At 64 and above its native branch directions implement a descending tag search. The authored code preserves that behavior for ascending, descending, duplicate and unsorted inputs; it does not substitute the strict `SfntFont::FindTable` service. Synthetic cases discriminate the exact 63/64/65 transition and every requested tag. All supplied original fonts take the linear branch.

The subblob constructor rejects zero requested length or an offset at/beyond parent length, otherwise clamps length to the remaining parent bytes. An oversized uint32 requested length can therefore produce a valid shorter view. A nonempty table descriptor initially has its own immutable flag clear, despite readonly data and a frozen parent. The whole-parent reference reports the shared parent flag, including changes caused by later queries. Empty table blobs use the native immutable empty value. `IsImmutable()` describes this logical native admission flag; returned byte views are const.

The portable supported domain is 64 MiB of raw font bytes and 1,048,576 cumulative range-validation operations. These explicit resource limits are not recovered native limits. Bounds and arithmetic are checked before access; a domain violation throws a contextual error. The typed value owns no native pointer, static face singleton or cache slot. Actual `VectorFont`/font-buffer integration must supply the existing pin and proven native face index at the corresponding resident-byte phase.

Ordinary `-O1`, strict C++20 warnings, ASan and UBSan pass three groups: clean pin/freeze/child lifetime, collection repair/selection/clamping/immutability, and original lookup branches plus an independent validation-work boundary. The differential executes original CRT/blob/COW/whole-font sanitizer/face constructor/real table callback/subblob creation/face destructor/closure destructor/child parent release code. Only imported Windows `HeapAlloc` / `HeapFree` services are modeled by a bounded fenced heap. Source data is readonly, parent reference counts are checked at each phase, and all native allocations must retire after the last child release.

The native corpus covers 2,991 cases, with 194 repaired and 718 rejected parents. It compares 1,531,728 evidence bytes, including all ten original font directories and tags, all known/unknown signature gates, TTC versions/offset repairs/edit ceilings, field mutations/truncations, the lookup transition, duplicate tags, table range/clamping boundaries and views before/after actual face destruction. Native/C++ output SHA-256 is `025f40e5ebd66096b8d0631084021cf3fa3261a2f27fad164727644bc7e92679`.

Synthetic admitted/view bytes through 4 KiB compare completely. Larger original views compare complete lengths and parent-relative offsets with first/last 32-byte samples, against original callback pointers and retained resource hashes. This establishes view geometry, bounded content observations and lifetime, not an exhaustive byte comparison of every original table payload. Original fonts stream once and are discarded; no original font/table dump is retained. The C++ weak pin observer agrees with the native live-parent/original-data relationship; actual engine-specific raw-font userdata callbacks remain a separate prerequisite.

Allocation failure remains outside the runtime fidelity claim. Direct assembly confirms an original constructor defect: the closure allocation failure branch `0x1403f26d6 -> 0x1403f277a` returns the static empty face without releasing the sanitizer-acquired parent reference. Face allocation failure at `0x1403f274d` releases parent/closure, then writes the requested index into the static empty face. The portable owner uses ordinary RAII and propagates standard allocation exceptions; it does not claim to reproduce that native leak/static mutation or original CRT errno/new-handler behavior.

Proof teardown keeps native face cache and shape-plan slots empty. Full lazy cache allocation/publication/failure and cache/plan teardown, nonresident OS table providers, engine font userdata lifetime, mutable face metadata setters, real nominal/variation font callback installation, generic buffer growth and full shaping remain open. The next concrete step is the original lazy face cache using these actual parent-pinned table views, the three sanitizers and proven lookup accelerators, with native allocation-failure paths recovered separately.

All 218 retained synthetic native cases replay independently through the final executable. Ten malformed CLI cases fail explicitly, and authored C++ exactly matches project formatting and CRLF.

Coherent public ASan/UBSan and portable Release fixtures pass at the 322/297 checkpoint; retained native witnesses and original metadata hashes validate only the documented component scopes. Full engine/cache/frame acceptance remains open.

The face and table-view owner requires caller serialization. The original lazy cache compares and stores face +68 without an internal lock; reference and immutability writes are also plain operations. Shared byte ownership extends lifetimes but does not establish concurrent face access. Engine-wide thread confinement remains unproven, and the later cache recovery must preserve this explicit serialized-owner contract.
