The portable driver honors replacement root slots and uses the actual existing Thread/scheduler when that registered class is the current root slot.

`InvokeThenDiscardResultInContext` is additive. The existing call implementation still captures its ordinary output. This route restores invocation depth and running state before retiring that output in the called context, then restores caller selection. It clears the facade Result before its separately returned owner, so a release callback's reentrant invocation can publish a new Result without that new owner being erased by the outer pop. Nested calls restore their actual outer Result. Script/native internal temporaries, error state and real suspended continuations remain owned under the existing VM rules. `InvokeWithoutResultInContext` retains its earlier cleanup timing.

The result-pop scope is an authored memory-safety boundary: non-owning counters prevent Reset/Release of the selected and caller contexts throughout this operation, including release callback reentry.
