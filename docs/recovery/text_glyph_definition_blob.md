# Sanitized GDEF blob and record entry

`GlyphDefinitionBlob` recovers the readonly table-blob path required before effective GDEF data can enter the native face cache. It admits a clean borrowed table, duplicates only on a permitted repair request, verifies repaired offsets, exposes immutable bytes, and applies the original length/class suppression policy. `UnicodeNormalizationBuffer::InitializeGlyphDefinitionProperties` performs the actual later GDEF record-entry phase on that admitted data. This is a prerequisite for the lazy face/layout cache; the whole cache is not yet implemented.

The logical input is `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. All Binary Ninja calls selected `candidate:view:1:UEU`. Original code, installation files and frozen caller/dotted-circle stages remain unchanged.

## Provider and blob lifetime

The original font bridge `0x1403a76e0` branches on stream `+0x20`. For a callback stream, `0x1403a7630` queries the table length, allocates bytes, reads the table through the original FT service `0x14039c870`, and creates a writable mode-2 blob with a free callback. For a memory stream, it creates a readonly mode-1 parent blob over the memory bytes, then a face whose provider retains that parent. The table-slice constructor `0x1403f6260` freezes and references the parent, clips the slice length, creates a readonly child and installs the original parent-release callback. The authored stage implements the readonly table-data profile with an explicit borrowed lifetime; it does not fabricate a stream callback or native face.

`0x1403f6190` creates a 96-byte blob with reference count 1 and explicit data/length/mode/userdata/destructor fields. Zero or at-least-2-GiB lengths produce the native empty blob. `0x1403f29f0` adds a reference; `0x1403f6350` releases it and, at the last reference, retires user data and then the blob. During sanitization, the temporary context reference is released before the result is returned. An invalid result also consumes the caller's blob reference and returns the immortal empty blob.

For readonly data, `0x1403f6070` refuses writable access when the blob is already immutable. Otherwise it allocates and copies the original data, releases the old userdata reference, and replaces it with owned writable mode-2 bytes/free callback. `0x1403f6490` freezes the admitted result. The authored owner borrows clean immutable bytes and owns only a repaired `std::vector`; copying and moving are disabled so its exposed span stays stable. Rejected repaired storage is released immediately. The original font/resource pin must outlive this owner. Retaining a face cache beyond that pin needs the eventual genuine parent/pin ownership integration and is not claimed here.

## Sanitization and repair

The complete original GDEF sanitizer is `0x140407870..0x140408129`; the verification traversal is `0x140409190..0x14040938d`. First, validation runs with edits denied. A request to erase an invalid nested offset increments the edit-request count and fails that pass. If the input blob is mutable, the sanitizer obtains writable storage and restarts validation. It allows at most 32 edit requests in a pass, writes only the specific two- or four-byte offset fields, and preserves the table's full length. After a successful pass that made edits, a fresh traversal must succeed without requesting further edits. Otherwise the result is the empty blob. Initially immutable data can be admitted unchanged but cannot be repaired.

The traversal preserves this order: major version, glyph ClassDef, attachment coverage/point arrays, ligature coverage/caret values/device offsets, mark attachment ClassDef, version-1.2 mark glyph sets, then version-1.3 item variation store/region/data structures. Every byte/array/relative-offset check is explicit. Nested invalid targets can request offset erasure; an offset already outside its parent's remaining span is generally a fatal failure before that repair point. Partial repairs are discarded if a later fatal check or exhausted edit budget rejects the blob.

Several observed native behaviors are intentionally retained:

- Unknown ClassDef, Coverage, CaretValue, Device and MarkGlyphSets formats can be admitted after their discriminating field is in range. The sanitizer does not invent support for their payloads. The native ClassDef query returns zero for unknown formats.
- ClassDef and coverage arrays are range-checked without imposing an additional ordering, glyph-count or value constraint. The subsequent native class query uses its original lower-midpoint binary search over the admitted array, including unordered synthetic arrays.
- Device formats 1–3 use the native packed-size calculation; a first size greater than the last requires only the six-byte header. Format `0x8000` also requires six bytes. Other device formats retain the native admission behavior.
- Item-variation checks retain the original short-count/region-count and array-width arithmetic. The native array guard rejects counts at or above `UINT32_MAX / element_width`.

The authored profile bounds GDEF input to 2 MiB and validation work to 1,048,576 checks, reporting a precise error if either bound is exceeded. These are explicit supported-domain guards, not native limits. All supplied GDEF tables fit. Allocation failure during duplication currently follows the standard exception path; original HeapAlloc failure, errno and new-handler recovery still require separate proof and integration.

## Suppression and late record entry

`ApplyLayoutSuppression` applies the exact policy from `0x1403feb46..0x1403fef4c` only after GDEF sanitization. Its inputs must be the **sanitized GSUB and GPOS blob lengths**, never arbitrary raw table lengths. The source contains 28 readable unconditional GDEF/GSUB/GPOS length triples and six further triples requiring glyph 5 to have class 3. It suppresses effective GDEF queries without discarding the retained immutable blob or changing its length. This distinction matches cache `+0x18` being replaced by the null table while the owned blob at `+0` remains alive. A zero/rejected blob never matches these triples.

`0x140404010..0x14040412c` runs after the neutral caller publishes final glyph-index content tag 2 and before GSUB. For every live input record it queries the effective GDEF ClassDef. Classes 1/2 yield properties 2/4; class 3 yields `8 | (MarkAttachmentClass << 8)` narrowed to 16 bits; all others yield zero. It clears the two private bytes at `+0x0e/+0x0f`. The enclosing caller immediately queries effective ClassDef presence through `0x14040a7e0` at `0x1403f404d`. If absent, `0x1403f405a..0x1403f40af` replaces each property word with 8 for category-12 marks when the character-state ignorable bit `0x20` is clear (or the current property bit `0x20` is set), and with 2 otherwise. Since the preceding effective-empty entry wrote zero properties, an ignored category-12 record becomes a base, and other categories become bases. The authored member includes this exact continuation; zero from the primitive `GlyphProperties` query is not advertised as the final empty/suppressed-GDEF record state. A nonzero ClassDef offset with an unknown admitted format prevents this fallback, matching the native presence query even though its glyph class query returns zero.

Glyph index, mask, unsigned cluster, character state, live counts, cursor, active/error state and output pointer/count remain unchanged. The member API requires the caller's returned `NormalizedGlyphContent::GlyphIndices` tag before mutation. The frozen normalization owner/state/record layouts are unchanged; its existing implementation is linked directly without a source copy.

## Remaining cache admission

The real `0x1403fe9c0` cache constructor requests and sanitizes GDEF, GSUB and GPOS in order, freezes each owned blob, applies GDEF suppression using their sanitized lengths, and allocates/initializes 12-byte lookup accelerators. GSUB/GPOS sanitizers traverse lookup payloads; existing metadata readers alone do not establish admission. Failure in cache or accelerator allocation tears down all owned/auxiliary blobs and arrays and must publish the original sticky-failed state. `0x1403f4d30` publishes an actual constructed cache or `-1`, discarding a redundant successful candidate if another cache appears before publication. These state transitions cannot be made successful by substituting raw `FindTable` results.
