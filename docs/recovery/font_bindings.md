# Font and PSBFont script owners

Target: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. All addresses are executable virtual addresses. Analysis explicitly uses the read-only PE view.

## Registration and construction

`0x14026b910` registers the actual `Font` class derived from Object. Constructor `0x14005ebf0` reports `can't create instance`. `0x14026bbe0` registers `PSBFont` derived from Font and constructor `0x14026b330`. The latter requires at least receiver plus an actual, nonnull PSBObject; trailing arguments are ignored. On success the assembly at `0x14026b474` returns status zero. Its `NEG/SBB/NEG/DEC` success calculation at `0x14026b412..0x14026b41c` relies on the allocated owner pointer; a simplified decompiler expression incorrectly appeared to return minus one on every path.

The constructor initializes native Object state, stores a borrowed SQPSBObject pointer at owner+0x50, and copies a 24-byte PSB ObjectInfo into owner+0x58 through `0x140227510`. This retained root keeps the borrowed PSB wrapper alive. Construction never calls a font parser, source texture loader or glyph rasterizer. Destructor `0x14026b210` clears this ObjectInfo through `0x140227690` before native Object cleanup.

Both classes explicitly register weakref thunk `0x140039f50`: it executes `sq_weakref` at stack index -1 and returns status one. Accordingly the authored registered method uses the last supplied argument, including the primitive passthrough behavior of the VM weak-reference API; it is distinct from the default delegate's exact-one-argument check.

## Provider and consumer coupling

PSBFont virtual provider entry `0x14026b870` allocates a fresh 0x60-byte MPSBFont for each call, obtains the original document pointer from SQPSBObject through `0x140229fb0`, and calls `0x1404c0990` with scale 1. Its next virtual entry `0x14026b8d0` copies the **underlying PSB ObjectInfo** into a consumer's root vector. It does not retain PSBFont itself.

The first Font branch in Indicator constructor `0x14026c490` calls both entries. The authored Indicator integration obtains the actual PSBObject from `ScriptFontBindings`, requests the existing bitmap font catalog, constructs a fresh bitmap provider/source wrapper set, and separately retains that PSBObject. Shared immutable metadata and physical cache textures do not merge mutable provider identities. Explicit or automatic PSBFont deletion leaves existing Indicators and their copied roots alive; task retirement remains Layer-owned as documented in [indicator_bindings.md](indicator_bindings.md).

`ScriptFontBindings` installs genuine Font/PSBFont inheritance, the abstract constructor, a bounded registry, constructor status zero, registered weakref status one and the singular Object-derived release hook. It validates document-wrapper liveness without requiring bitmap schema at construction. Instance records use exact VM generation identities, including during class finalization. The VM, Object and PSB adapters must outlive native instance retirement and VM Close. Derived cleanup releases the PSB root before Object notification and completes all available cleanup if a notification fails.

## SystemFont in the supplied Windows executable

Registration `0x14026beb0` creates SystemFont derived from Font, constructor `0x14026b490`/factory `0x14026b500`, registered weakref, and literal method name `ready`. Its constant vtable at `0x1405f93d8` contains destructor `0x14026b270`, provider `0x14004b530`, and consumer-root copier `0x140030f20`. Exact assembly is `xor eax,eax; ret` for the provider, `xor al,al; ret` for ready callback `0x14004b570`, and `ret` for root copying. Thus this class supplies no font provider, never becomes ready and retains no font/resource roots. Constructor/destructor are the only direct references to this vtable in the analyzed executable. No asynchronous loader or fallback service is inferred from its name.

The factory accepts exactly one through three native stack values, including the receiver. With no user arguments it stores scale 1 and an empty name. One argument goes through actual float conversion `0x140222e90`: integers, float32 and bool values convert; other ordinary types leave zero through `0x140227920`. The ordered `0 > scale` comparison rejects negatives, including negative infinity, while retaining negative zero, positive infinity and NaN bits. A second argument uses the VM tostring path, then native `strlen` and owned string copying at owner+0x58; the first NUL terminates the stored name. It only constructs native Object state and those two values. Destructor `0x14026b270` releases the string through `0x14003a560` before Object cleanup.

The authored SystemFont binding preserves this constructor, ancestry, unused scale/name values, original method names and ready-false behavior. Names are bounded to 65,536 bytes each and 16 MiB in aggregate, with combined PSBFont/SystemFont instance capacity. It intentionally rejects an Indicator request with `SystemFont has no native font provider` before borrowing a view/task or loading textures. This is a documented safety deviation: the native Indicator Font branch creates an MIndicator around a null provider and can later dereference that null pointer. The port does not invent a font to mask the unavailable native provider.

One thousand bounded prepared original SystemFont constructors execute 154,610 unchanged instructions. Original integer/float/bool conversion, ordered comparison, strlen/string copy, literal provider/ready routines and string destructor run with observer boundaries for VM stack/tostring/error APIs, native Object base setup/tail, caller heap and script attachment. All 5,000 projected status/scale/ready/provider/cleanup words and 3,815 stored name bytes match; 647 constructors succeed. Native vector SHA-256 is `4d9c5f30634cc84deb47a607f6e4bf75daefe75c08b582824e07c501558ffd6d`. These are original constructor/string semantics, not a whole native VM or allocator ABI comparison.
