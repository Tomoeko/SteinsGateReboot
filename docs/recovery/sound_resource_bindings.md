# Sound resource control and script bindings

The portable Sound resource domain now owns the recovered configuration loads, archive references, buffered cue owners and actual Serial/Parallel task sets. `ScriptSoundBindings` connects eight resource operations to this live owner: `load`, `unload`, `getLoading`, `getLoaded`, `loadArchive`, `unloadArchive`, `getArchiveLoading` and `getArchiveLoaded`. Loads use the host's actual mounted body mappings, cipher seed, target spec and explicit wrapped-file policy. They retain ordinary cache references and use the existing background reader and PSB receiving lane. No precompleted configuration is inserted.

The caller must keep the cache, mounts and file processor alive around `SoundResourceControl`; the VM and Sound owner must enclose `ScriptSoundBindings`. Drive prepared file-reader work, then `AdvancePostLoop`. This performs actual Parallel updates, Serial load/completion updates, cue retirement and configuration/archive retirement in that order. `Close` requires finished actual task borrows; it flushes and closes the existing CPU cue/source owners before releasing configuration resources. This explicit host teardown is authored policy: the original global MSound shutdown/reset caller remains unrecovered.

The extracted `io::PrepareMountedResourceRead` preserves the current Resource service's strict identity, size, physical mapping and decoder bounds. The existing script helper delegates through it with the same limits. Sound can therefore share one real pending or completed PSB cache cell with Resource without duplicating the physical read. Configuration/archive filenames remain exact; a missing mounted entry reports the still-unrecovered native loose-file/path fallback.
