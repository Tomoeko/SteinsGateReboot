## Submission, mix, and scheduling

`PlanSoundSubmission` reconstructs the loader's buffer fields. End-of-stream is always set; play begin/length and callback context are zero. Without an explicit resource loop, negative requested count maps to repeat count 255, zero to zero, and positive count to count minus one. With a resource loop, nonpositive requested count maps to 255. ADPCM loop begin and length are separately rounded down to whole samples-per-block. Values are preserved even where a later API rejects a native request; the planner does not silently clamp or rewrite them. `nosrc` disables conversion only when the source rate is exactly 48,000 Hz. WMA submissions retain their cumulative packet table count.

Retained hidden, game-only-silenced submissions agree: PCM payload 1,933,884 bytes uses loop begin 18,097, length 948,845, count 255; the first observed WMA voice submits 19,331 bytes/13 packets with no loop. Source acceptance is distinct from successful decoding; see [CrossOver observations](crossover.md) and [WMA recovery](wma.md).

`EvaluateSoundMix` follows `0x140383ec0` and backend `0x1403925f0`. Gain multiplies voice, resource, group, archive, master, and mute in that order using single precision. Pitch adds resource and voice octave offsets; the backend requests `2^pitch` unless conversion is disabled. The ARM float overload matches 309 finite CPU-only pitch/loudness vectors from the original baseline CRT path; initialized-game CPU dispatch and nonfinite numerical parity remain open. Common pan writes left/right diagonal entries. Source-specific pan multiplies each destination coefficient by its resource coefficient, then by gain. Mono folding adds the first two source rows' left/right coefficients; ordinary `MSound` update always enables folding. The lower-level backend also has an individual-row branch. Negative gain and values above one remain unclipped. [Microsoft's matrix contract](https://learn.microsoft.com/en-us/windows/win32/api/xaudio2/nf-xaudio2-ixaudio2voice-setoutputmatrix) confirms destination-major indexing. `AccumulateSoundMix` applies that linear map to caller-owned interleaved buffers; native engine summation and resampling numerical parity are not yet measured.

`SoundVolumeToLinear` and `SoundVolumeFromLinear` recover the numeric volume unit operations at `0x14037f8d0`, `0x140380e50`, `0x140384610`, and the unit branches of `0x140381390`. The native setting initially enables loudness conversion: signed `3^(log(abs(value))/log(2))`; getters invert it with base two and log base three. Exact zero and plus/minus one bypass math, preserving signed zero. Explicit suffix `V` stores linear gain, `L` forces loudness conversion even when the setting is disabled, and `DB` converts amplitude with `10^(dB/20)`, unity for nonnegative input and silence at or below -96 dB. Direct bytes identify `L`, not `B`. Unordered decibel comparisons reach the power branch; they are not silently clamped. Full native string-number parsing, locale and nonfinite payload behavior remain open.

Pause masks are voice 1, global 2, group 4, archive 8. A first pause requests stop; subsequent reasons only extend the mask. Explicit voice resume (`0x140382c50`) waits until all reasons clear. Global/group/archive resume (`0x140382900`, `0x140382af0`, `0x1403829a0`) requests start even if another reason remains. Preserve this native behavior.

`SoundVoiceSchedule` reconstructs `0x140391cd0`: scan all pools in order, apply changed running requests to the current nonzero operation set, commit all deferred operations, then examine draining callbacks and flush pending stops. Operation sets increment and skip zero on wrap. Native retirement tests **current buffer context**, not queued-buffer count: assembly `0x140391e4e` checks the first returned qword. Null context clears active/draining. Buffer-end callback `0x1402f89b0` separately clears active. Stop flushing is deferred until after commit; type-two wrappers additionally trigger an immediate commit. The portable schedule does not perform resource loading, choose slots, or provide that wrapper. [XAudio2 operation sets](https://learn.microsoft.com/en-us/windows/win32/xaudio2/xaudio2-operation-sets) establish the original atomic-change contract. Callers serialize schedule calls and callback events; OS callbacks must not directly race its state.
