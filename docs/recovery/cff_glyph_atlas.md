# Default CFF glyph atlas rasterization

Target: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. All addresses are executable virtual addresses. Binary Ninja inspection explicitly used `candidate:view:2:UEU`, read-only.

## Original caller and portable contract

The actual glyph renderer `0x140089110` clears its six-word result, loads the glyph through `0x14039c140` with flag 8, decomposes the private slot outline through `0x14039d930`, and obtains actual curve bounds through `0x140426f90`. Its floor/ceil phase checks nonempty extents before padding. For border zero, it asks `0x1400369c0` for an atlas region, then wraps the returned **atlas interior address and atlas-wide byte pitch** in a borrowed PRGB32 image through `0x140427b10`. It translates the path, draws white, and ends the context. The original does not render into a separate contiguous bitmap and copy it afterward.

A null create-info at `0x140428320` uses the default synchronous context. `0x140454f40` initializes NonZero fill rule (value 0) at context+0x3d9, default alpha 255 from `0x14064dec0`, and the 0.2-pixel approximation tolerance. Its band selection starts at 64 and halves down to 8 while `width * band_height * 4 > 0x40000`; the null-info path creates no worker thread. The caller sets SrcCopy opcode 1 through virtual slot+0x68, clears the borrowed image through slot+0x140, sets white fill through slot+0xb8, and fills path geometry kind 21 through slot+0x178. The static provider/cell/pixel semantics are documented in [glyph_raster_solid_copy.md](glyph_raster_solid_copy.md).

`0x1404282c0` ends/releases the context rather than copying a bitmap. Owner unlock `0x140087020` delegates to `0x1404f8e90`; when CPU shadow bytes exist, that function only clears the locked flag, retaining upload-required state. The returned six words are atlas U, atlas V, padded glyph left, negated padded top, width and height. The negated top is a drawing translation, not a downward-positive path top.

`PreparedCffGlyphRaster` owns immutable bounded path/cell preparation before texture mapping; `RasterizePreparedCffGlyphInAtlas` consumes it directly into the borrowed atlas. A moved-from preparation is rejected before packing mutates. The existing convenience adapter preserves the same native comparisons.

`RasterizeDefaultCffGlyphInAtlas` composes the recovered default CFF glyph owner, cubic path/bitmap planning, translated finite-interior edges, area cells and strided solid-copy kernel. It returns a value containing allocation coordinates/extents and the two signed glyph placement values. Pixel bytes remain borrowed from the atlas owner. A scoped nonthrowing unlock releases only the successfully acquired CPU mapping. Empty glyphs or unavailable atlas mapping return no allocation; rejected fonts, geometry, dimensions and storage report errors. Geometry and bounded cells are prepared before mutating atlas packing. Per-glyph surface work is limited to 1,048,576 pixels; extents must fit 1..65534. This preparation allocates temporary CPU geometry and belongs in glyph-cache preparation, outside ordinary frames.

## Remaining scope

The default border-zero CPU path is supported. Whole `0x140089110` context construction/end/destruction and FT load are not replayed together in the dormant executable harness: the adapter composes independently checked stages with the executable-derived settings contract and retained initialized-native outlines. This is not a new whole-caller initialized capture or an all-font native pixel proof. Stroked borders, true out-of-rectangle clipping, TrueType hinting/quadratic outlines, font fallback/shaping, full cache/application policy, shader binding and final text pixels remain open. The separately checked fixed texture lifetime and per-interface cache coupling are documented in [glyph_atlas_owner.md](glyph_atlas_owner.md); they do not close whole-caller or GPU pixel acceptance. No original game, native GPU operation or raster observation was launched for this tranche.
