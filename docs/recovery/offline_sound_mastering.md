# Offline Sound mastering leaf

`OfflineSoundMastering` binds a bounded, stable batch of actual `BufferedSoundCues` channel/source slots to a real macOS `AVAudioEngine` in manual offline mode. Configuration, archive, cue and decoded-sample owners enclose the graph until `Close`; selected IDs/slots must remain allocated through that close. Construction validates actual queued samples, source rates, destination matrices and unit frequency ratios before OS graph creation. Each real source node pulls through `ConsumeMixedChannelFrames` into preallocated storage. Actual system output planes and `manualRenderingSampleTime` supply the returned frames and timeline. This leaf adds no device-ready state or script registration.

The matching primary SDK explicitly describes manual rendering as disconnected from audio devices. Offline mode is enabled before touching mixer/output nodes, because the SDK warns earlier node access may configure hardware. The actual manual format is checked against the explicit caller format; native mastering's default channel/rate arguments do not establish stereo or 48000 Hz. OS callbacks access the serialized source owner only on its preparation thread. C++ exceptions remain inside the callback and are rethrown by the enclosing render operation. Other callback threads reject before source access. There is one system render per caller request, with no retries. A platform-local operation boundary translates `NSException` from graph creation, engine-state queries, rendering, format and timeline queries. It retains the first operation/cause as a C++ exception; nested graph/state operations preserve the inner first failure. Later calls reject before accessing the system engine. Caller extent/thread preflight errors do not poison an otherwise unchanged graph. Close remains available to release the real graph after any operational failure, and sample consumption already performed is retained. Graph close fences callbacks, stops and detaches actual nodes before releasing its engine, and does not flush or complete portable cue samples.

Independent bounded PCM PSBs feed actual worker/cache/configuration/archive/cue owners. Three groups check actual system sample sums and completion, paused callback/remaining-frame retention, rejected input/thread access and retirement of an actual borrowed cue before rendering. A fourth group raises actual Foundation `NSException` objects and C++ errors inside the same platform boundary; it checks translation, no subsequent work invocation, original operation retention and nested nil-reason handling. A containing operation that swallows an inner C++ failure and then raises an actual Foundation exception keeps the first stored C++ kind, operation and exception; the later thrown exception is still translated. These controlled boundary exceptions do not represent an observed AVAudioEngine fault. The real retired-cue callback error also prevents later rendering/format/timeline access until close. Recovered `pContext == nullptr` stays separate from queued samples and CPU callback activity. Direct leaf/fixture units use ASan and UBSan; the coherently pinned public core is linked as built, so this proof does not claim whole-core sanitizer instrumentation. The fixture uses prepared physical reads and an explicit 48000 Hz stereo output geometry; it proves no original-script loader, hardware, default mastering format, native timing or XAudio2 summation parity.

The separate original-instruction witness targets supplied `sgre_steam.exe` SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`, explicitly `candidate:view:1:UEU`. Nine setup/destruction cases at `0x1403918f0`, `0x1403918a0`, `0x140391ef0`, `0x140392580` and `0x140391b20` execute 5,916 instructions at 272 PE-exact visited sites. The native owner is `0xfa8` bytes, pools have 32/8/1 slots, and successful setup obtains four mastering-details words before setting byte zero and publishing the owner. Failed setup still publishes, skips interface/library release while its completion byte is false, and subsequent setup does not retry. COM and audio interfaces, allocations and auxiliary registration are observed ABI boundaries with independent opaque outputs; they are not actual native engine/device creation. The failed release omission is retained evidence, not the portable RAII policy.

Dynamic cue/node rebinding and retirement, actual hardware/service startup, focus and native clock ownership, non-unit pitch/resampling, type2 streaming and complete native `playVoice` remain open. Existing first-party decoders produce the sample buffers; AVFAudio is not used to decode original encoded formats. The next producer check is actual dynamic source-pool/graph ownership with native commit and retirement order, followed by a separately admitted output-device service.
