# Motion texture wrappers and slots

Target: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. The explicitly selected PE analysis and executable bytes remain unchanged. Shared GPU identity and decoding are documented in [texture_cache.md](texture_cache.md).

## Recovered ownership

Motion layer construction `0x140529270` creates eight null wrapper slots. Import callback `0x14052b000` constructs a separate 72-byte texture wrapper, then calls registration `0x14052bb40`. Registration writes the wrapper's sampler through `0x14054b1f0` before searching for the first null slot. A full slot vector doubles its logical extent; vector growth `0x140528a50` preserves earlier pointers and initializes new entries to null. Each occupied slot owns a separate 16-byte registration containing the wrapper pointer and a one-byte borrowed flag at `+0x08`.

Release callback `0x14052af40` receives the resource-manager subobject at motion-layer `+0x28`; its slot pointer at `+0x148` is the layer's `+0x170` vector. An owned registration disposes the texture wrapper through `0x140548880` and frees its 72-byte owner before freeing the 16-byte registration and clearing the slot. A borrowed registration only frees and clears the registration. Releasing an empty in-range slot has no disposal effect. Slots reuse the first empty index; their vector does not shrink.

`MotionTextureWrapper` owns exactly one shared-cache reference. Distinct wrappers can share one uploaded texture while retaining separate local filter fields. `MotionTextureSlots` imports owned wrappers or registers a checked weak borrow of the exact wrapper. Borrowing neither acquires a cache reference nor extends the wrapper's lifetime. All aliases observe that wrapper's local sampler writes. `0x14052c710` writes the manager's filter fields, then visits occupied slots in increasing index order; wrapper-local fields and the physical shared texture's latest fields remain separate. Newly registered wrappers receive the manager's current values.

The shared cache outlives all wrappers and slot owners. Preparation preallocates bounded slot records; the native eight-slot doubling remains observable without allocation during filter changes or disposal. Generations, bounds, foreign-cache checks, expired-borrow errors and rejected cleanup reentry are authored safety restrictions. Explicit `Close` attempts every owned wrapper and reports cleanup failures afterward; this safety close is not a full native motion-manager shutdown claim. Directly created render-target wrappers selected by native texture byte `+0x32`, source overrides and complete Layer project ownership remain separate recovery work.

## Validation

One thousand bounded private instruction fixtures cover 50,000 registrations, releases and filter changes, including borrowed aliases, scalar/SSE4.1 first-null searches and 2,233 original vector reallocations. Registration, resizing, copying, zero initialization, wrapper fields and release instructions run unchanged. Only bounded heap allocation/free, the independently measured shared texture destructor, and the physical sampler service are isolated. The native run executes 8,338,432 instructions; portable sanitizer replay matches every slot, extent, sampler field and disposal event with zero differences. Both output traces have SHA-256 `d38950a4328e6d088ce7b38ebcd7181fd9eae4f708ed7883a8bbf723aa5fa142`. Compact reports and reproducible bounded inputs remain ignored under `Files/research/scene/`.

Independent sanitizer fixtures additionally check generation reuse, two-manager cache sharing, exact borrowed-wrapper identity, expiry without ownership extension, capacity rollback, GPU retirement before slot clearing, and cleanup despite platform failures. The integrated Metal fixture checks exact A8 pixels from two motion managers before and after one manager closes, then stale backend rejection after final wrapper release. Full native scene clipping, batching, resource registration and GPU pixel fidelity remain open.
