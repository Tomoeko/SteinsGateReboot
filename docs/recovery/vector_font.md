# Vector font owner and size state

Target: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. The addresses below are executable virtual addresses. Analysis used the exact PE view without metadata or byte changes.

`text::VectorFont` owns the immutable raw resource pin before its borrowed SFNT/CFF readers. This keeps original font bytes alive until every private reader retires. Each script wrapper owns an independent mutable size state; immutable resource bytes may be shared. `SfntFont` retains the first native-preferred charmap `(platform,encoding)=(0,3)` or `(3,1)`. The original constructor at `0x1400878a0` selects that first match. A font lacking that map is explicitly rejected: the original FreeType default-map fallback has not been recovered.

The same constructor maps shaping mode 0 to Latin/LTR, 1 to Cyrillic/LTR, 2 to Arabic/RTL, 3 to Han/LTR, and 4 to Han/TTB; native direction values are 4/5/6. The language defaults to `en`. Native language preparation at `0x1403a3a00` first caps the byte string to 63 bytes. The intern helper `0x1403a38a0` uses the exact table at `0x140608b60`: ASCII uppercase becomes lowercase, `_` and `@` become `-`, ASCII lowercase/digits/hyphen survive, and every other byte becomes NUL. The observable canonical string ends at the first such byte. Empty input produces a null language; nonempty invalid input may produce a nonnull interned empty language, preserved by `HasLanguage`. The wrapper still retains its original CString language separately. Unknown modes leave native script/direction fields uninitialized, so provider preparation rejects them instead of guessing. These are configuration values, not an implementation of general shaping.

The actual size setter is `0x140087ee0`. `0x140087ed0` is the separate TextRenderVectorFont interface size selector: it writes that wrapper's requested-size field at offset `0x18`. It must not be substituted for the SQVectorFont/core setter. The size word at `0x50` starts as `0xffffffff`. The getter `0x140087ec0` zero-extends this word and converts it to float: its initial result is 4,294,967,296. The setter executes signed-64-bit `CVTTSS2SI`, stores its low 32 bits, and skips work when that word is unchanged. NaN, infinity and out-of-range values therefore produce low word zero; this differs from the common signed-32-bit conversion sentinel.

On a changed word, the original converts the unsigned word multiplied by 64 into signed 32-bit character height. Overflow produces `INT32_MIN`. `FT_Set_Char_Size` at `0x14039f5a0` receives width zero and 72 dpi on both axes, copies height to width, and clamps dimensions below 64 to 64. The portable owner retains the raw request and applies that verified one-pixel minimum for supported CFF glyph preparation. The unchanged initial `-1` sentinel does not configure a size.

`PrepareGlyph` uses the existing first-party `CffGlyphFont` with original SFNT metrics, Type2 programs and default hinting. The accepted scope remains normalized 1000-unit CFF fonts, supported private dictionaries and sizes 1..2000. Requests outside that range are rejected. TrueType outlines, arbitrary matrices, general HarfBuzz shaping/positioning, fallback font selection, stroke rasterization and font atlas cache/GPU ownership remain open. The class does not manufacture a shaped run or claim that metadata parsing reproduces every native constructor side effect.

`BindMetricServices` adds a separate one-time applied-domain admission for the same owner. It requires the actual initialized HB axis signs explicitly, preserves them across `SetSize`, and binds the genuine flags-2 CFF/table callbacks to `NormalizationFont`. Current positive integral requests 1..2000 with original vertical tables are admitted. Sentinel, zero, overflow and other current requests remain rejected by this service because initial active FT size and arbitrary failed-size preservation are not established. No HB scale update is added to the setter. Hinted `PrepareGlyph` remains unchanged; see [live metric services](vector_font_metric_services.md).

## Validation

A prepared CPU oracle ran the unchanged original setter/getter and the actual `0x14039f5a0` clamp for 10,000 sequential random and boundary float values. All 60,000 projected words match: stored size, getter float bits, presence/raw/clamped height and whether the size dispatch ran. The trace SHA-256 is `a6f3e0f5c6bada23f03a7b05f9f38fd5194188de3da2414c3869cd61ccb61935`; 290,995 original instructions executed. The private core/face-holder and stack were prepared inputs. The five-word request at `0x14039f100` was copied at an observer boundary; the downstream FreeType size driver was not invoked in this oracle.

A separate 1,000-case oracle executes those unchanged original language routines with all 256 byte values, mixed inputs and the 63-byte cap. All 2,000 language-presence/length words and 4,145 canonical bytes match. Its trace SHA-256 is `17a4f0e82d8094b38047cd6d698d5ed65bbf60501b64496feec0742eb346ed40`; 464,411 original instructions execute. Two bounded allocator observers and an isolated private CPU cache list are preparation boundaries; the original game shared intern cache is untouched.

Strict-warning ASan/UBSan fixtures cover raw-byte lifetime, all five mode mappings, charmap lookups, independent private sizes, unchanged sentinels, signed-zero/NaN/infinity/conversion limits, and a genuine synthetic CFF rectangle through the accepted Type2/hint/metric implementation.

A bounded original-resource scan prepares all ten supplied SFNT fonts, totaling 170,516,620 streamed bytes and 439,302 glyphs, without retaining decoded copies. It exercises 655,360 BMP lookups through each provider's selected map, prepares 30 CFF samples, and confirms explicit outline rejection for all four TrueType fonts. Existing font corpus notes contain each original decoded-font hash; this scan adds owner integration coverage, not an independent new charmap or pixel fidelity claim.
