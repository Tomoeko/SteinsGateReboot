# Compact Font Format recovery

Target: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Resource identities and hashes are in [vector fonts](vector_fonts.md). Authored CFF readers preserve original bytes and borrow immutable sfnt resource storage.

`CffFont` reads the OpenType single-font CFF 1.0 header, Name/Top-DICT/String/Global-Subr INDEX structures, CharStrings, CID Font-DICT arrays, private widths/local subroutines and FDSelect formats 0/3. INDEX offsets are one-based and monotonic; byte ranges, counts, cumulative records, numeric encodings, dictionary fields and glyph/dictionary indices are checked before access. Integer DICT operands retain signed values; real operands decode bounded decimal nibbles using the standard classic locale. Matrix values are metadata and are not applied to glyph geometry at this stage. Charstring execution, charset/encoding names and hinted glyph outlines are separate operations.

The six original CFF fonts contain 217,831 glyphs. All are CID fonts, use FDSelect format 3, have top matrix `[0.001,0,0,0.001,0,0]`, and have no per-FD matrix. Dictionary counts are 15/9/9/18/19/18 in resource order. All glyph/local/global program byte lengths and SHA-256 values, private widths, matrices and dictionary routing matched 856,431 independent FontTools 4.66.1 oracle values across 319,097 programs. The corpus was streamed and duplicate font samples removed; public evidence retains no extracted programs or outlines.

Reachable glyph and decoded subroutine programs use relative move/line/cubic commands, stem/mask declarations, local/global calls, return and endchar. Arithmetic, flex and random operators were not observed in those programs. The analysis tool left 543 unreferenced/context-dependent subroutines undecompiled; their byte hashes are validated, while their operator content remains unclassified. That distinction does not authorize silently accepting an unsupported operator.

Synthetic fixtures exercise CID/non-CID private dictionaries, borrowed program ownership, decimal matrices, default/nominal widths, local/global/empty indexes, direct/ranged FD routing and malformed header/offset/selection/real-operand cases. Strict warnings, AddressSanitizer, UndefinedBehaviorSanitizer and source format checks passed. Format references are Adobe's [CFF specification](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5176.CFF.pdf), [Type 2 charstrings](https://partners.adobe.com/public/developer/en/font/5177.Type2.pdf), and Microsoft's [OpenType CFF table](https://learn.microsoft.com/en-us/typography/opentype/spec/cff).

`ReadCffGlyphOutline` now executes the observed Type 2 move/line/cubic variants, optional initial widths, stem/mask byte boundaries and local/global subroutines. Global calls retain the glyph's selected local dictionary. Bias depends on subroutine count; operand stack, nesting, executed bytes, stem count and emitted commands are bounded. A subroutine endchar ends the entire glyph, while return resumes its caller with the remaining operand stack. Implicit contour closure emits an explicit close command. Unsupported escaped arithmetic/flex/random and composite endchar operands fail with glyph/program/depth context.

All 217,831 original CFF glyphs decoded successfully and matched independent FontTools command counts, exact command-coordinate SHA-256 values and charstring widths: zero differences across 15,742,494 commands. The reference generation and portable decoder each streamed one font/glyph at a time and retained only compact hashes. These are raw design-space commands, before font matrices, native scaling/hinting, drawing-axis conversion or rasterization. Synthetic geometric fixtures cover line/curve variants, multiple contours, short/fixed operands, explicit/default widths, shared subroutine stacks, mask bytes, return/end behavior, recursive cycles and bounded expansion. Sanitizers and strict warnings pass.

`CffFontDictionary::Hinting` retains the private blue/family-blue arrays, horizontal/vertical stem-snap arrays, optional standard stem widths, BlueScale/Shift/Fuzz, ForceBold, LanguageGroup, ExpansionFactor and initial random seed. Delta arrays become absolute font-unit values. Blue/family arrays have checked paired counts; stem-snap arrays are limited to 12 values. Scalar operand counts, boolean ForceBold, signed integer metadata and finite accumulated values are checked. Missing arrays/widths stay empty/absent and scalar defaults follow the CFF specification. Floating source values remain metadata; conversion to native integer/fixed-point fields is separate.

The streamed original-font metadata comparison covered all six resources and 88 dictionaries: zero differences across 1,539 scalar/array values against retained independent FontTools metadata, SHA-256 `262e37b76f6fa1e89149b69824bf5e1b98a3708cf5207111794df6d33a045040`. No duplicate font or glyph corpus was retained. Focused fixtures preserve delta accumulation/defaults and reject unpaired/excessive arrays, wrong scalar counts, malformed booleans and fractional integer fields.
