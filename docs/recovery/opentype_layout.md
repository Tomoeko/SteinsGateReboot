# OpenType layout metadata and glyph classes

Target: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Addresses are virtual addresses. Font resource identities/hashes are in [vector-font recovery](vector_fonts.md). All source bytes and analysis metadata remain unchanged.

`OpenTypeLayoutFont` borrows validated sfnt layout/GDEF table bytes and prepares owned script, language, feature and lookup metadata. Its existing constructor selects GSUB; the typed `OpenTypeLayoutKind::Positioning` overload selects the actual GPOS table. Common metadata parsing is shared, with `Kind`, `Lookups` and `FeatureVariationsOffset` exposing the selected table identity. `SubstitutionLookups` and `ApplySingleSubstitution` reject GPOS explicitly. `OpenTypeSubstitutionLookup` retains the existing API name as an alias of the common serialized `OpenTypeLookup` value type; this does not alias native providers or executable classes. It preserves ordered feature indices and duplicate feature tags, required-language features, lookup flags, and subtable identities. Missing tables remain absent. Big-endian offsets/counts, coverage ordering, glyph limits and class values are checked; table sizes and cumulative validation records are bounded, including repeated aliases to a large coverage table.

The reader supports GSUB/GPOS versions 1.0/1.1 metadata, coverage formats 1/2, single-substitution formats 1/2, GDEF versions 1.0/1.2/1.3 metadata, and glyph/mark-attachment class formats 1/2. A flags-zero single lookup returns its first covered subtable's replacement. Signed deltas use modulo 65536. Other lookup types, filtering/context behavior and nonzero feature variations fail explicitly when asked to apply a single lookup; their metadata is retained. This is not a complete shaping engine. Format references: [OpenType common layout tables](https://learn.microsoft.com/en-us/typography/opentype/spec/chapter2), [GSUB](https://learn.microsoft.com/en-us/typography/opentype/spec/gsub), [GPOS](https://learn.microsoft.com/en-us/typography/opentype/spec/gpos), [GDEF](https://learn.microsoft.com/en-us/typography/opentype/spec/gdef).

Native script selection `0x14040acc0` tries requested tags in order, then `DFLT`, `dflt`, and `latn`. Native language selection `0x14040ab10` tries the requested tag, then an explicit lowercase `dflt` language, then selects the default language system with index `0xffff`. Native feature query `0x14040a860` scans the selected language's feature indices in order and returns the first matching feature tag; required-feature retrieval is separate at `0x14040aa20`. Portable `SelectScript`, `SelectLanguage`, and exact `FindFeature` retain these distinctions. No matching script is represented explicitly. Returned selection tags borrow this reader's metadata.

Unchanged native helpers `0x140417f30/417c70` convert the observed shaping profiles `Latn/Cyrl/Arab/Hani` to `latn/cyrl/arab/hani`, with `DFLT` as the second candidate, and `en` to `ENG `. The portable selection API accepts OpenType tags directly; broader language conversion remains open. Native feature planning `0x1403f3730` requests `vert` for vertical direction. In the retained SourceHanSansTC font, Hani default-language `vert` is feature 426, lookups 45/49; lookup 45 substitutes glyph 1461 with 65158. That exact change appears in the initialized-font U+3042 TTB capture. GDEF classifies captured U+0301 glyph 253 as mark, class 3; the shaper's subsequent zero-advance policy is not implemented by class lookup.

`HasGlyphClasses` preserves the actual nonzero GDEF glyph-class offset. `MarkAttachmentClass` returns its separate full serialized 16-bit class value. `GlyphProperties` returns the original packed GDEF substitution-property word: base `2`, ligature `4`, mark `(attachment << 8) | 8` narrowed to 16 bits, and zero for unclassified/component glyphs. These properties are distinct from Unicode character properties. Class definitions validate both array and range formats, glyph bounds, sorted nonoverlapping ranges and permitted glyph classes; mark-attachment values retain their full 16-bit width. Inputs remain borrowed and must outlive this reader.

The exact original initializer `0x140404010` queries GDEF classes through `0x140402fc0`, writes the packed word at glyph-info `+0xc` and clears bytes `+0xe/+0xf`. Codepoint (`+0`), mask (`+4`), cluster (`+8`) and the remaining auxiliary word (`+0x10`) remain unchanged. The later single-substitution helper `0x140405560` preserves property bits `0x60`, adds replacement GDEF properties and bit `0x10`, then calls `0x1403a6460` to copy the 20-byte record and replace its codepoint. This extension supplies the exact GDEF values; it does not yet implement that buffer mutation or Unicode fallback.
