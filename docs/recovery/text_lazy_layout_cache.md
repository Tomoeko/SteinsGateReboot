## Serialization evidence

Preparation, table queries, logical-flag observation and lifetime transitions for one face and its shared parent descriptors require caller serialization. No concurrent-use guarantee is exposed. `0x1403f4d30` tests and writes face `+0x68` with plain instructions; its final publication at `0x1403f4d83` is an ordinary store. Blob references at `0x1403f29f0`, face references at `0x1403f2840` and immutable flags at `0x1403f6490` also use ordinary loads/stores. The table callback and subblob constructor freeze the shared parent without synchronization.

A deterministic unchanged-instruction interleaving pauses one preparation immediately before `0x1403f4d83`, runs a second preparation using a distinct emulated stack, then resumes the first. The first store overwrites the second complete cache. Face destruction frees only the first candidate; the second cache and its two one-byte zero-count arrays remain unreachable (144+1+1 bytes). This proves the helpers do not synchronize publication internally. It does not establish the original engine's global thread-confinement policy. Standard shared-pointer control-block operations do not make the shared logical flag or cache publication synchronized.
