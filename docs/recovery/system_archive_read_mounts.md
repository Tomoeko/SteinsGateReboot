# Script requests to actual archive readers

`System.mountArchive` is registered by the original `sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Read-only Binary Ninja analysis explicitly targets `candidate:view:1:UEU`. Callback `0x140285ba0` reads three actual strings, copies their C-string prefixes using `strlen`, converts an optional numeric/boolean fourth argument through `0x140222c70`, queues `0x1404d5e30`, pushes integer zero and returns one value. Additional arguments are ignored. The queue owns copies of the three identities, the flag and an initially empty receiving cell; registration does not imply that an index is loaded.

`ScriptSystemBindings::ConfigureArchiveReadMounts` connects that request to the existing actual `ArchiveMounts` receiving owner. Its resolver borrows immutable physical inputs prepared outside ordinary frames. The returned prefix, index/body identities and cipher input name must equal the actual script request; the body requires an explicit physical filename. It then calls `QueueReadMount`, which requires the genuine bound `FileReadProcessor` and its admission limits. No decoded index, completion flag or physical path is inferred from a lookup token.

The existing nested file-reader phases perform physical index reading, shell/PSB decoding, temporary reader retirement and ordered mount publication. The retained PSB owner and explicit body mapping survive that temporary reader. The adapter performs no filesystem read or decode in its callback. It does not choose the application's resource directory, discover loose files or supply an application frame clock. The alternate physical read mode remains an explicit unsupported error. The existing prepared-index configuration remains available for its documented diagnostic profile.

Two direct-source ASan/UBSan groups use an independently serialized 391-byte archive, a wrapped raw Zstandard frame, the actual VM/System callback, real background worker and actual mount receiving owner. They verify native zero return, C-string truncation, float-to-boolean conversion, deferred publication through all nested retirement gates, retained index output and exact physical body/range mapping. Mismatched identities, invalid arguments, empty resolvers and unavailable mode requests fail before queued reception changes. The exact 32 C++ units and 46 recursive headers are pinned, without a core-library link or source interposition. The 6.7 MB executable is hashed and retired.

Original instruction execution, native worker timing, application bootstrap/resource directory selection, alternate modes, full mounted game startup and complete gameplay remain open. This is a real callback-to-reader connection with independently checked authored behavior, not acceptance of the whole native application.

`System.isExistentFile` registration `0x140287c00` selects `0x140285a10`; its Raw counterpart selects `0x140285ae0`. Shared wrapper `0x140043a70` stringifies physical argument two, and each callback consumes the C-string prefix. The ordinary query unconditionally appends `.m`; Raw preserves the name. Native `0x1404d5480` normalizes separators through `0x1404d6230`, resolves the currently published archive map through `0x1404d70f0`, and compares original versus mapped body identity (`0x1404d55df`–`0x1404d562c`). Equal identities return false even after a successful index hit. These queries perform no physical-file stat or resource load. The actual ArchiveMounts-backed callbacks pass independent pending/publication, suffix, normalization/case, string conversion, NUL, extra-argument, self-mapping and unmount checks; this is not whole-game startup acceptance.
