## Actual transition order

- Seek `0x140511640` selects the first exact time or previous frame before the first greater time, with count-minus-two clamp. It decodes/prepares slot 0, then decodes/prepares slot 1, resets current slot to zero and dirties the frame. An exact-time current action follows both preparations.
- Forward `0x140518160` crosses at equality. At every crossing it toggles the current slot, reuses the former current slot as the next following frame, and queues the newly entered action. After all crossings, only the final unprepared slots are prepared, in slot-0/slot-1 order (`0x1405187cd/0x1405187f4`).
- Reverse `0x14050a6b0` crosses only below current time. It toggles and decodes the new current slot at every crossing, queues entered actions, then prepares the final unprepared slots in slot-0/slot-1 order (`0x14050ac95/0x14050acbc`).

A decoded frame does not immediately overwrite motion controls during crossing. Motion metadata preparation occurs at the final selected slots. Consequently, specified motion metadata in an intermediate crossed frame can have no effect on either control when the final frames omit it. Hidden frames and missing `0x80000` motion content perform no control write; previously used slot values remain intact. The independent default fixture deliberately crosses specified controls and finishes on absent/hidden frames, distinguishing this behavior from eager per-crossing decoding or fresh default controls.
