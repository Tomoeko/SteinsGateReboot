# Buffered cue and archive ownership

`BufferedSoundCues` connects actual delivered SoundConfig/archive definitions to owned first-party decoded sources for pools0/1. It owns active and retiring cue payloads, real source-slot assignments, recovered mix decisions and a 28-bit ID lookup. Caller-driven source-rate consumption produces real interleaved samples; the unit-frequency matrix path accumulates those samples into supplied output without allocation or I/O. The actual cache, reader and `SoundConfigurationLoads` enclose this serialized owner. It does not register script `Sound` or assert native audio-service/device readiness.

`SoundArchiveCueResource` retains the exact configuration/archive objects and their existing acquired cache references. Its definition and PSB getters borrow those owners. Shared ownership is confined to this real relationship between a live/retiring resource owner and a cue using its definitions/samples. It neither copies the PSB nor calls another cache Acquire. Removing a filename/archive lookup cannot destroy its backing while an actual cue still owns this borrow. Load cancellation/latches/diagnostics keep their existing order. `CanClose` refuses destruction until serial and cue resource borrowers finish.

## Recovered order

The logical target is `STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`, analyzed explicitly as `candidate:view:1:UEU` without metadata mutation or byte patching. Static original assembly and direct PE bytes establish these phases:

- `381930` first sweeps finished active cues through `380d60`/`383b80`, then polls retiring cues through `380970`. `390a20` searches completed, non-unloading configurations in filename order; an empty archive name searches completed archives in name order. `3947d0` returns the actual matching definition after the archive completion latch.
- Uniqueness and slot selection retain ordered prior evictions even if a later candidate blocks the request. A rejected request commits its earlier stops and leaves their retiring payloads for a later retirement phase. Accepted selection calls commit at `3824d7` and retirement at `3824df` before checking/marking the selected free slots.
- Channel preparation calls `391bb0` at `38259e` and continues without inspecting a source return value. Source `3921a0` can fail and clean up its source/callback while the outer channel loop continues. Mixing `383ec0` at `3825ce` and commit `391880` at `3825d6` precede ID generation and active payload publication. `3825e9` applies the exact `0x0fffffff` mask. This CPU API reports Prepared, PartiallyPrepared or FailedSources explicitly; an all-failed logical cue ID is not source/audio readiness.
- Stop `383b80` resumes a paused source before requesting stop/flush, erases ID lookup, then transfers the resource/channel payload into retirement. `380970` retains it while any channel callback is active, then returns its actual slots and frees the cue payload. Pooled source/callback storage remains until later reuse or service close.

The port transfers stable owned payloads between lists instead of copying native list nodes. It preallocates unpublished payload/list/ID storage before source preparation so allocation failure can retire source storage before callback storage and release its resource borrow safely. Per-channel unsupported source errors stay explicit while other channels continue. Successful decoded-source callback activity gates logical cue completion; failed channels have no nominal source object. The native null `pContext` drain quirk is preserved separately by `BufferedSoundSources`; its recovered drain flag cannot stand in for actual remaining sample completion.

Unloading through this owner stops the actual selected archive/configuration cues before removing resource lookup. An upstream resource unload also marks its exact archive/configuration objects as unloading; the next cue phase stops their actual borrowers. Retirement releases the last cue borrow only after real consume/flush completion, and the enclosing serial phase then releases archive/configuration cache references. Cue retirement retains idle pooled source storage, matching the recovered boundary.

## Validation and limits

Six bounded strict ASan/UBSan groups use the actual cache, background call manager, file read processor and complete synthetic PSB backing. They consume independently specified PCM through the recovered gain/pan matrix; preserve archive/configuration references through requested stop and actual flush; distinguish partial/all-failed channel preparation from real sample ownership; preserve earlier slot/uniqueness evictions on rejection; verify actual ordered archive lookup and selected-archive unload; and check source pause, slot reuse, strict backing and unavailable type2/non-unit pitch boundaries. The exact direct-source/recursive-header closure is pinned; the 5.7-MB test executable is hashed and retired. This proves the authored ownership and consumption behavior, not measured native callback timing.

Successful ordinary consumption allocates nothing and performs no resource I/O. Preparation performs bounded decoding and prepares a bounded mix workspace. Actual output channel geometry and gain factors are supplied; native startup/service defaults are not inferred. Non-unit frequency ratios fail mixed consumption before consuming samples; raw source-rate frames remain available. Group/global/focus pause masks, clock/resampling, continuous device2, native audio-service startup/shutdown and script method publication remain open. Existing configuration/archive regression groups still require current shared-core validation when this overlay is published.
