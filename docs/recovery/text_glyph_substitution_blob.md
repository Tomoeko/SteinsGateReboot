# GSUB sanitized blob admission

`GlyphSubstitutionBlob` recovers the default GSUB blob sanitizer at `0x1404087d0` in logical input `STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Addresses are executable virtual addresses in the explicit Binary Ninja view `candidate:view:1:UEU`.

The constructor consumes a borrowed immutable GSUB byte span or the genuine first-party `SfntFont` table. Clean bytes remain borrowed. The font byte owner must outlive the blob; this value does not fabricate the original face callback or retain a font pin. Repair creates one private copy, and rejection releases that copy. Status distinguishes absent, accepted, repaired and rejected tables. `Bytes()` and `Length()` expose sanitized data, independently of the strict raw-table metadata reader. No lookup application or effective face cache is claimed by this admission owner.

Native traversal first validates the common layout header (`0x140409390`), then the GSUB-specific LookupList (`0x140406880`) and Lookup (`0x140409cd0`). The initial pass denies writes but counts requests. A mutable blob may obtain writable storage through the original copy-on-write path (`0x1403f6430` / `0x1403f6070`) and restart. A successful editing pass requires a further pass with zero new requests. The native request ceiling is 32 (`0x1403f1b40`). An initially immutable blob cannot repair. Invalid admission consumes the input blob reference and returns the native empty blob; authored ownership publishes an empty view and `Rejected` status.

The following are direct executable-derived checks, verified against unchanged native code:

- ScriptList, Script and LangSys bounds/offset repair (`0x140406c50`, `0x140409b30`, `0x140409530`), FeatureList/Feature bounds (`0x140406a60`, `0x140408ce0`), generic lookup header/MarkFilteringSet bounds (`0x1404066a0`, `0x140409580`). Tags, lookup indices and list ordering receive no invented semantic checks.
- `size`, `ss` and `cv` parameter checks (`0x140408e60`) and the original legacy `size` offset rebasing. Invalid feature-relative parameters are erased before rebasing from FeatureList origin; the native edit-count adjustment is preserved. Other parameter tags admit their bounded offsets without invented payload interpretation.
- Version 1.1 FeatureVariations, condition sets and alternative feature tables (`0x1404063c0`, `0x140408ab0`, `0x140409000`). Native ConditionSet uses a 16-bit count, while FeatureVariationRecord uses a 32-bit count. Conditions with unknown format remain admitted after their format word is bounded.
- All eight GSUB lookup types (`0x1403fd880`): single, multiple, alternate, ligature, context, chained context, extension and reverse chained single. Context/chain rules follow `0x1403fce00`, `0x1403fcc60`, `0x1404099b0`, `0x1404059b0` and associated offset-array helpers. The native context-rule range includes `glyphCount + 2*lookupCount` words, rather than subtracting the first glyph. Zero input count rejects format3 context/chain context; the counted input segment in a chain rule admits zero with no array.
- Coverage/ClassDef validators preserve native unknown-format admission and selected nested offset erasure (`0x140408c30`, `0x1404070c0`, `0x140406f80`). A zero lookup subtable offset resolves to the native null table outside the sanitizer range and rejects the entire lookup. Zero offsets in counted optional coverage/rule arrays are skipped.
- Extension traversal follows positive unsigned 32-bit relative offsets, rejects zero target offset, and preserves the lookup-level extension type consistency check. Type7 cannot be the common extension type. Unknown lookup types/subtable formats are admitted after their format word is bounded. Extension traversal is iterative; it introduces no guessed native recursion limit.

Relative-offset range failure returns failure before requesting repair of that field. A containing optional offset may still be repaired when its target validator fails. This distinction and original visitation order determine which bytes are zeroed and when the 32-request ceiling is reached.

The portable supported domain bounds input to 2 MiB and cumulative validation range work to 1,048,576 operations. These are explicit parser resource limits, not recovered native limits. Exceeding either throws a contextual error instead of silently replacing a table with empty. Arithmetic is checked before arrays; the native strict count test `count < UINT32_MAX / width` is retained. The supplied original font corpus fits these bounds.

Validation uses ordinary `-O1`, strict C++20 conversion warnings and ASan/UBSan. Three test groups cover borrowing/COW/immutability, fatal bounds, native format/context behavior, extension handling, admission byte bounds and repeated-offset work bounds. The independent native differential exercises all ten original font GSUB tables, complete synthetic lookup types/formats, every synthetic truncation, nested field mutations, shared script/feature/variation structures, parameter name-ID boundaries, legacy `size` offsets, extension consistency and edit ceilings. Original resources stream through the existing first-party font reader and are discarded; no original font/table duplicate is retained.

The native proof runs original blob construction, reference, writable-copy, sanitizer, freeze and destruction code. Only imported Windows `HeapAlloc` / `HeapFree` are supplied by a fenced bounded platform heap model. Original CRT wrappers execute unchanged. Input bytes are mapped read-only, allocation fences and complete retirement are checked after every case. Retained receipts contain compact synthetic replay vectors, code-range hashes, resource/table hashes and aggregate stream hashes.
