The image branch at `0x1402926e0` requires equal logical dimensions before calling `0x14005d1f0`. The latter copies tightly packed four-byte image rows into the mapped destination using its actual row pitch. It preserves every channel and alpha byte. The binary branch requires a character array of exactly width × height × 3 bytes, copies the original binary view, then expands RGB triples into BGRA bytes with alpha 255. Destination row padding is untouched. These byte operations are independent of the texture's selected color-mode descriptor; no automatic channel correction or premultiplication is introduced.

Mapping at `0x1404f8a70` sets the lock byte `+2` and upload-dirty byte `+0xc` independently. The CPU-shadow path borrows `+0x18`; row pitch comes from `0x1404f8b30`. Unlock at `0x1404f8e90` clears the lock byte without clearing upload-dirty and calls D3D Unmap only for a locked non-shadow texture. The public helpers implement the writes into a borrowed `std::byte` surface, accepting integer byte buffers through standard `std::as_writable_bytes` views. Mapping, dirty publication, unlock, GPU upload and ownership remain separate responsibilities.

VM argument/type/image lookup and bounded allocation/release are observer boundaries; no game process, OS or GPU calls execute.

Three independent fixture groups verify RGB channel ordering and alpha, arbitrary BGRA bytes in unaligned padded surfaces, and rejection before mutation. The authored safety boundary requires positive dimensions, at most 64 MiB of pixels/mapped rows, exact input lengths, sufficient destination storage and nonoverlapping input/destination. It rejects the original unsafe overflow/invalid-pointer domains explicitly. Script class attachment, decoded image ownership, texture creation/upload, background work/cancellation and physical device failure behavior remain open.
