Target: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Addresses below are virtual addresses. No reference bytes or analysis metadata were changed.

## Input and font boundary

`SQTextRender.render`, registered in `0x14003ce90` and implemented at `0x14003ef00`, constructs a UTF-8 string and converts it through `0x1404c7840`. It then calls the `TextRender` subobject at `MTextRenderImpl +0xb0`. Valid BMP scalars produce one UTF-16 unit; supplementary scalars produce a high/low surrogate pair. The portable `DecodeTextCodeUnits` preserves these units behind a UTF-8 interface and allocates only when preparing text. It validates input and caps each preparation at 1 MiB of UTF-8.

The original converter assumes enough input bytes and includes legacy five/six-byte UTF-8 forms. The authored converter rejects malformed, overlong, truncated, surrogate, and out-of-range scalar encodings with the failing byte offset. It reproduces valid modern Unicode input rather than the native routine's unsafe malformed-input behavior. Explicit-length input retains NUL units; the original script wrapper's preceding C-string construction supplies its own terminating-NUL boundary.

The unmodified original converter ran on 1,000 bounded synthetic strings under the existing Unicorn harness. Each case stayed inside the original small-string capacity, avoiding native heap imports. Every emitted unit matched both independent Python Unicode conversion and the portable reader. Retained tests cover encoding-width boundaries, mixed Japanese/supplementary input, invalid encodings, contextual offsets, and the allocation limit. Bitmap code-unit lookup, nominal sizing, and its independent instruction measurements are documented in [font recovery](images.md).

## Measured elements and line arithmetic

`PlaceMeasuredTextElement` implements the fitting-element path of `0x14002dc40`. For cursor `(x,y)`, nominal element size `(w,h)`, and pitch `p`, horizontal placement is `(x,y-h)` and the next cursor is `((w+x)+p,y)`. Vertical placement is `(x,y)` and advances to `(x,(y+h)+p)`. Pitch is included after each appended element, including the final element; alignment uses the advanced cursor. Ink size and glyph bearing do not replace these nominal metrics.

`TextElementReachesLineLimit` implements the preceding overflow predicate: a positive line extent triggers handling when `cursorX+w >= extent` horizontally or `cursorY+h >= extent` vertically, unless that direction's overflow permission is enabled. Equality enters handling. This predicate does not decide which earlier elements the prohibition/word-grouping rules move to another line.

Line finalization at `0x14002e330` takes the maximum nominal height horizontally or width vertically, then the configured minimum line extent. `TextLineCrossExtent` preserves the original MAXSS operand selection on equal values, including signed zero. Native alignment field 0 means center, 1 means end, and every other value means start. `TextLineAlignmentOffset` subtracts the advanced cursor from the available extent in float, halves in double for center, truncates to a signed integer, and converts that integer to float. Negative offsets truncate toward zero. Out-of-range native integer conversions are rejected explicitly.

One thousand complete original fitting-element append executions matched all 4,000 placement/cursor words. Separately observed original basic blocks matched 1,000 overflow decisions, 1,000 line-alignment words, and 1,000 cross-extent words. Cross-extent cases include empty, unrolled, and tail loops; overflow cases include exact equality. These comparisons exercise the stated operations, not complete rich-text layout or line-list ownership. Retained instruction vectors and malformed/overflow checks passed AddressSanitizer and UndefinedBehaviorSanitizer. Prepared numerical operations allocate no storage.

`FinalizeTextLineGeometry` applies recovered line geometry to caller-owned positions. Horizontal lines add the alignment offset to X and the maximum nominal height to Y; vertical lines add alignment to Y and optionally subtract half the cross extent from X. Horizontal next-line progression adds cross extent and line spacing to Y, then resets X to the configured line start. Vertical progression subtracts cross extent and line spacing from X, then resets Y. Horizontal cross overflow occurs only beyond the positive render height; vertical cross overflow occurs only below X=0 when render width is positive. Exact cross boundaries are accepted. The caller retains or discards the actual line entries; rejected geometry leaves its buffers unchanged.

Five hundred original line-geometry executions stopped before the allocator-dependent line ownership copy. The original late cursor-advance blocks ran separately from the captured state. All 5,028 descriptor, overflow, cursor, and element-position words matched the portable operation. No copy/allocator helper was stubbed; these measurements intentionally exclude that ownership phase. Two retained instruction-derived lines exercise horizontal alignment and centered vertical elements. Boundary rejection/permission, unlimited extents, and preflight failure checks passed sanitizers. The dormant executable harness does not initialize the original CRT heap. A later coordinated initialized-game probe exercised the complete fitting-line ownership lifecycle described below.

## Prepared wrapping decisions

`UpdateTextWordBoundary` recovers the state updates at `0x14002dcde..0x14002e2b0`. Exactly one U+0020 unit marks an ASCII space. A transition from that space to another element records its one-based position as the trailing word start; repeated spaces preserve the prior marker until the next element. U+3000, multiple spaces in one element, and empty elements are not that ASCII-space token. Native field `+0x5d` disables this tracking when nonzero. Finalization clears the line's word marker and preceding-space flag at `currentLine +0x30/+0x34`.

`PlanTextLineOverflow` prepares the prior-line retention and replay tail from `0x14002dc40` without allocating or moving owned entries. An active word marker takes priority: every existing element from that marker through the end moves to the next line in its existing order. The old advanced cursor remains in force when finalizing the retained prior line. The owner must not recompute that cursor from its shorter element list.

Otherwise, exact UTF-16 substring membership in the line-start prohibition list selects an overhang allowance. Before the configured allowance is exhausted, the incoming element stays on the current line and the overhang counter increments. When exhausted, the existing overhang elements move, followed by one ordinary predecessor unless that predecessor is also in the line-start list. A normal incoming element can move the final existing line-end-prohibited element. The native conditional sequence is retained, including the one-element move for consecutive prohibited endings. This is not Unicode line-breaking classification, case folding, or unordered code-point membership. Empty substring search succeeds, as it does in original `0x140030ea0`. Settings borrow prepared owner lists; guard limits bound counts, string lengths, and worst-case substring-search work.

One thousand original word-boundary paths, one thousand complete original prohibition-search executions, and one thousand first-action overflow routes matched 4,164 observed state/search/branch words. The first-action traces stop before element clone/removal/finalization ownership operations; they establish branch selection and accepted-overhang updates, not complete tail replay. Retained word-state vectors and independent policy/safety fixtures passed AddressSanitizer and UndefinedBehaviorSanitizer. Full initialized-game tail movement and lifecycle comparisons remain open.

An ignored, separately gated text probe ran twelve synthetic complete lines in the initialized original game. It verified the exact executable and four function signatures, constructed a private native `TextRender`, appended valid caller-owned SSO elements, finalized and captured bounded copied-history data, then destroyed original CRT allocations with deleting-destructor flag zero. The existing research shim preserved thread state. The 20-second launch kept windows hidden and speaker output zeroed, left original saves/configuration hashes unchanged, and terminated its game process. ## Prepared block bounds and alignment

`FinalizeTextBlockGeometry` recovers the numeric history phase at `0x14002f2e1..0x14002f8b9`, after current-line finalization and before render/link-list ownership. It expands each supplied line's existing bounds by ordinary nominal geometry, then each ruby entry's stored geometry. Ruby coordinates enter the bounds exactly as stored; parent position is not added at this phase. The first history line replaces the prior block bounds; subsequent lines expand their union. An empty history retains prior block bounds.

Horizontal block center/end alignment uses render height minus block bottom. Center multiplies that float by 0.5 before truncating to a signed integer; end truncates the difference directly. Vertical center uses `(renderWidth - blockLeft) * -0.5` before truncation; vertical end truncates the positive difference and negates that integer. Ordinary positions receive the converted integer offset on Y horizontally or X vertically. Ruby offsets and line bounds remain unchanged by this shift; block bounds receive it on their cross-axis endpoints. A zero offset skips element-position addition while still adding float zero to block endpoints, preserving the native signed-zero distinctions.

One thousand unchanged original numeric phases, using caller-owned prepared history/deque/ruby storage, matched all 59,598 block bounds, line bounds, offset, ordinary-position, and ruby-position words. Cases include empty history/lines, ring wrap, zero through nine ordinary elements, zero through three ruby entries, negative metrics, fractional and negative extents, and signed zero. Retained native horizontal/vertical/empty fixtures and independent initial-bound, truncation, failure-without-mutation, and work-limit checks passed strict warnings, AddressSanitizer, and UndefinedBehaviorSanitizer. Preparation allocates nothing and borrows distinct owner-held element/ruby storage. These observations do not establish rich-parser ownership, link hitboxes, render-list ordering, or native text pixels.

## Directive lexer

The original rich parser dispatch at `0x140032c43` uses byte selectors at `0x140034f04` and target entries at `0x140034ee4`. Newline finalizes a line; `#`, `$`, and `&` collect a payload through the next semicolon; `[` collects through the next `]`. These payloads respectively feed color parsing, a string-expansion callback, inline object measurement, and a directive callback. Nested brackets and escaping inside these collected payloads are not inferred.

`TextMarkupReader` preserves this lexical phase with borrowed UTF-16 payloads and explicit source offsets/lengths. It caps preparation at 1,048,576 units and reproduces the render boundary's first-NUL termination. It emits individual code units, including surrogate halves, and performs no shaping, font lookup, directive callbacks, or allocation. Plain rendering mode preserves every unit except newline's line-break classification.

The percent dispatch at `0x14003310b` has its own operand rules. Immediate controls `B/C/L/R/S/r/;` consume no further operand; `b/i/k` consume exactly one unit. `e/s` consume one unit unless it is `#`, in which case the following hexadecimal payload extends through semicolon. A leading decimal digit selects the font-size percentage. `a/d` collect decimal digits; `p/n` also collect minus signs; these numeric scanners leave the first unrecognized unit for the next token and consume an optional semicolon. `f/l` collect name text through semicolon. `w/t/D` collect decimal digits or a `$`-prefixed variable payload through semicolon. The variable prefixes target original virtual callbacks; `D` uses an integer callback while `w/t` use string expansion. The directive identity is retained for the owner to make that distinction. Unknown percent controls swallow through the next semicolon, as the original does. The lexer preserves payload text rather than broadening native numeric grammar or applying guessed defaults.

The backslash table at `0x140034f58/0x140034f7c` selects `i/k/n/r/t/w/x` and literal escapes. `\n` produces a line break and `\t` a measured tab unit. The other controls remain explicit escape tokens for the recovered owner: current/reset line start, segment timing boundary, space advancement, and parser-state reset occur on different original branches. An unknown escape produces its next code unit. Unterminated payloads consume only available input; a trailing percent/backslash prefix is represented as an incomplete directive. Source ownership and truncation stay visible.

One thousand unmodified original operand paths stopped before semantic, allocator ownership, and font/OS callbacks. All 4,040 observed token-class/source-length/payload units matched the portable lexer. This measurement includes every percent operator, all escape branches, numeric stops, variable payloads, literal Japanese input, and bounded unterminated directives. Independent boundary tests passed strict compiler warnings, AddressSanitizer, and UndefinedBehaviorSanitizer. It does not establish applying rich directives, expansion results, ruby, links, or reveal timing.

## Prepared render order, links, and reveal boundaries

`PrepareTextRenderPlan` recovers the prepared-list phase at `0x14002f987..0x14002fd4e`. Ordinary elements enter the render list in history-line order. Nonnegative link indices select owner-local link state; negative indices remain unlinked. Each linked element appends its identity and explicit-length UTF-16 text, preserving embedded NUL and surrogate units. Existing link state remains and receives these appended values; the caller owns its reset lifecycle.

Link rectangles combine only contiguous runs. A run counter increments when the link index changes and again after every line, including empty lines. Each link retains its last run number. A matching last run expands the last rectangle; otherwise a new rectangle uses that element's nominal position/size. Switching away and back, or crossing a line, splits rectangles even for the same link. Ruby entries do not enter this ordinary list or its hitboxes.

More than one reveal segment enables stable ascending time ordering. Original comparator `0x14002f200` compares ordinary element times; `0x14002af80` insertion and `0x14002b340` merge paths preserve equal-time history order. Link state remains in history traversal order. All reveal boundaries except the final sentinel update their first-element count: each boundary time truncates to a signed integer, converts back to float, and advances a single forward cursor past times strictly below that threshold. Decreasing thresholds do not rewind it; equality is excluded. With zero/one segment, order and boundary counts remain unchanged.

One thousand fresh and one thousand retained-state original phases matched all 125,338 order, link identity/run/bounds/text, and reveal-boundary words. Caller-owned bounded buffers avoided native growth allocations while original string append and both sort paths ran unchanged. Retained native vectors and independent equal-time stability, empty-line splitting, prior-state preservation, embedded-NUL, fractional-threshold, terminal-sentinel, and safety checks passed strict warnings and sanitizers. ## Reveal segment retiming

`RetimeTextRevealSegment` recovers complete original `0x140030250`. The owner supplies history-line elements followed by current-line elements in their original traversal order. The selected tail begins at the requested element index. Its available duration is `defaultDelay + lastRelativeTime`; the requested duration is the integer target time converted to float, minus the segment base time.

A nonpositive requested duration selects the greater of available/requested duration and leaves element times unscaled. A positive requested duration scales relative times when forced or when the target shortens the available duration. An unforced later target extends the segment end while retaining the original relative letter times. Each selected output is `scale * relativeTime + segmentBaseTime`, with separate multiplication/addition as in the native code. The cursor then advances its base by the selected duration, records the total element count as the next segment start, and clears next-relative time. An empty selected tail changes nothing. It preserves native MAXSS signed-zero operand selection and preflights finite results before mutating output.

One thousand complete unmodified native function calls exercised empty, unrolled, and tail loops across multiple history/current line ring layouts. All 13,016 element/cursor output words matched the portable operation. Three retained independent instruction vectors plus natural/shortened/extended/forced-duration and invalid-result checks passed sanitizers and strict warnings. This implements retiming in native text time units; the script render owner's conversion to the game clock, reveal advancement, markup timing callbacks, and visible-text draw selection remain open.

The portable command therefore uses the existing sprite vertex values and preserves the input word; it does not assign a guessed font blend/filter/render mode.

One thousand original color/vertex/index instruction paths matched all 26,000 prepared output words, including nonzero native glyph base indices and mirrored/fractional geometry. ## Prepared element draw passes

`PrepareTextElementDrawPlan` recovers the draw caller at `0x1400362a0`. The final element position is the render origin plus the prepared element position. Bold selects native font style 1 and takes precedence over italic style 2; regular is 0. Stored main/shadow/edge colors at element offsets `+0x54/+0x5c/+0x68` each undergo `BSWAP32` before entering the font interface. The portable pass carries that resulting RGBA queue word, which is subsequently packed by the bitmap vertex path already described above.

An enabled edge draws only when its signed integer width is positive. An enabled shadow draws at the element position plus its signed integer offset in both X and Y, with width zero. The integer first converts to float, then each coordinate is added separately. Main fill always draws at the original element position with width zero. The order is edge, shadow, main; effects do not displace the main position.

After all ordinary passes, the original caller repeats those phases for ruby through `0x1400367b0`. For each phase it visits every ruby entry in order, selects that entry's ruby font size and the element's ruby font identity, then adds its prepared local offset to that phase's position. `PrepareTextRubyDrawPass` preserves this addition and the color/width/phase identity. The prepared owner must keep phase traversal outside ruby-entry traversal; drawing all effects of one ruby entry before the next would change native order.

One thousand unchanged original element draw callers and ruby traversals executed with supplied logging font interfaces, covering zero through four ruby entries, every style/effect flag combination, nonpositive edge widths, fractional coordinates, and large signed shadow offsets. All 1,000 callback counts and 80,904 callback words matched the portable plan. ## Vector fonts and prepared shaped runs

`FontInfo` construction at `0x140039860` distinguishes PSB bitmap fonts from `SQVectorFont` resource fonts. `SQVectorFont` construction at `0x140088970` retains a resource name, integer shaping mode, and language string, defaulting to mode 0 and `en`. Its lazy loader at `0x140088b10` requires a raw resource and constructs the embedded vector-font implementation at `0x1400878a0`. The integer argument is a shaping mode, not a face index.

The native vector-font constructor initializes embedded FreeType, opens face index 0 from the resource bytes, and selects the first character map with `(platform,encoding)=(0,3)` or `(3,1)`. It creates a HarfBuzz font and buffer, with the following explicit script/direction profile. Unknown modes leave fields uninitialized in the original and are not a recovered fallback.

| Mode | Script tag | Direction value |
| --- | --- | --- |
| 0 | `Latn` | LTR, 4 |
| 1 | `Cyrl` | LTR, 4 |
| 2 | `Arab` | RTL, 5 |
| 3 | `Hani` | LTR, 4 |
| 4 | `Hani` | TTB, 6 |

TextRenderVectorFont interface size selection at `0x140087ed0` converts the requested float through signed 64-bit truncation and stores its low 32-bit word at wrapper offset `0x18`. This differs from the SQVectorFont/core size setter `0x140087ee0`, which updates core offset `0x50` and skips unchanged words. The core getter `0x140087ec0` returns that unsigned word as float; its initial `0xffffffff` reports 4,294,967,296. The measurement/run callbacks update FreeType character size to that integer times 64, with 72 dpi in both directions. One-unit measurement at `0x140088320` and string-run shaping at `0x140088630` reset the buffer and explicitly set direction, script, and language before adding UTF-16 and shaping. They pass the configured 16-byte feature records; an empty feature range passes null. The FT-backed HarfBuzz font data at `0x1403a6f50` stores load flags 2, disabling hinting for shaping metrics. Its horizontal-advance callback `0x1403a73d0` passes those flags to the native advance reader, then rounds 16.16 to 26.6 with `(advance + 0x200) >> 10`. This differs from the later flags-8 hinted outline load. These identifications are executable-derived and cross-checked with the [FreeType sizing API](https://freetype.org/freetype2/docs/reference/ft2-sizing_and_scaling.html) and [HarfBuzz buffer properties](https://harfbuzz.github.io/setting-buffer-properties.html).

`PrepareTextGlyphRun` implements the post-shaping loop at `0x140088728..0x1400887fa`. Each signed 26.6 offset converts to float and multiplies by 1/64 before adding the prior float pen position. Glyph IDs are retained in order; cluster metadata is not substituted for a glyph ID. Each advance independently converts/scales, then adds to the float pen. Y is preserved at this stage; outline-to-drawing conversion happens later. The signed final advance matches the separate native measurement sum. Input count and caller-owned output capacity are checked before mutation; preparation allocates nothing. HarfBuzz's [glyph position reference](https://harfbuzz.github.io/harfbuzz-hb-buffer.html) distinguishes offsets from advances.

Two thousand original post-shaping instruction paths, using preallocated output storage, matched all 99,610 glyph-ID/position/advance words. ## Recovered call chain and next operations

`0x1400356c0` constructs `MTextRender` and calls `0x14002c040` for its `TextRender` base. That constructor initializes horizontal mode, font-size families, inter-character/line spacing, alignment, prohibition strings, and layout state. The roles and script-facing overrides must be recovered before importing those defaults into an authored engine.

`0x14002dc40` appends a measured text element, handles line overflow and prohibition strings, and advances the cursor. `0x14002e330` finalizes a line, applies alignment, updates line bounds, and advances between lines. `0x14002f280` finalizes complete bounds, applies block alignment, and builds the rendering list. This call-chain identification is executable evidence; it does not establish complete layout semantics.

The next recovery step is authored line ownership and initialized-game overflow-tail replay comparison, then applying the rich-text parser with its ruby, links, style stacks, timing, and reveal controls. Font registration/fallback, system-font measurement and shaping, glyph rasterization, full text draw commands, and native scene/text capture comparisons remain open. Input conversion and measured-element/line geometry must not be reported as a complete text engine.
