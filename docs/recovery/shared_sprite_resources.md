# Shared graphics resources across Metal targets

The supplied `sgre_steam.exe` has SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Read-only Binary Ninja evidence at virtual-screen traversal `0x1404fa250` and target switching `0x1404c6130` uses the same global graphics owner, device/context, shader arrays and texture identities across targets. The earlier registry instead constructed independent sprite renderers, whose valid handles were rejected by another target.

A target may now share the actual resource owner of another SpritePassRenderer. The shared first-party object retains the Metal device, ordered command queue, compiled library, uploaded texture slots, generations, aggregate texture accounting and prepared pipelines. Each target keeps its own color surface, upload slots, submission identity, readback and mutable binding/target-copy services. The shared constructor requires matching global texture/pipeline limits; target-specific dimensions and geometry limits remain separate. This is a macOS ownership adaptation, not original MGraphics layout or complete target-switch recovery.

Texture and pipeline handles identify the live common resource domain. A sibling target can sample an uploaded texture and use its prepared pipeline without another upload or shader compilation. Release/reuse invalidates the same generation in every target. Retiring the creator target leaves shared assets alive while sibling targets retain their actual resource owner. Mutable resource retirement holds a weak reference to that common registry so it returns the global allocation charge even after its creating target closes; operations that borrow the closed target still reject through their existing lifetime guard.

The baseline uses the original two independent renderer constructors and fails the common-pipeline identity check. The corrected direct source passes actual opaque pixel checks at distinct target extents, foreign-domain rejection, common budget/generation checks, creator-target retirement and a real mutable resource lifetime edge. The mutable test uses the actual four-byte texel plus three256-byte upload allocation, then proves retirement permits slot/budget reuse. The initial incorrect four-byte fixture budget and baseline new-API link failure are retained. Actual recursive compiler dependencies, source/shader/current413 libraries are pinned before and after ASan/UBSan checks; products are retired. No window or audio is opened.

The installed Apple SDK describes enqueue as appending a command buffer to its queue. Shared targets use one actual queue and serialized submission. This preserves a necessary ordering boundary; cross-target write/sample hazards, exporting target color textures, shared active mutable bindings, native target switching/scissor restoration, actual Driver screen tasks, native shader pixels and complete game frames remain open.
