# One-time launch configuration

This is authored startup policy, not a recovered original settings format. `LaunchConfigurationStore(workspace).LoadOrCreate(optional_installation)` accepts the installation path once and stores actual absolute paths in ignored `Files/config.json`. With no config, the known supplied `Files/STEINS.GATE.REBOOT` directory is also discovered. A later launch needs no asset/shader/seed/save/dimension/audio arguments. The loader returns the actual archive seed in memory; it never embeds that seed in source or config.

The platform owns actual visibility, aspect-fit resize, minimize/close and fullscreen transitions; this module does not launch a window, alter original System debug, or claim native window equivalence.

The strict flat JSON reader accepts escaped strings and nonnegative uint32 numbers plus typed booleans. Schema1 requires its exact11 fields; schema2 requires its exact15 fields. It rejects malformed/truncated JSON/UTF-8/surrogates, duplicate/unknown/missing fields, unsupported versions, noninteger or out-of-range numeric fields, empty/relative/control-containing paths and oversized inputs. Reads stop at64KiB; path strings stop at4096 UTF-8 bytes. Required assets are the executable, nine index/body pairs, movie directory and actual shader files. Their presence is checked without decoding all archives. Missing assets or bad explicit seed files are reported; they do not silently reset a structurally valid user config.

Each complete write uses a freshly reserved directory on the destination filesystem and one rename. Failed replacement keeps the previous primary intact; there is no remove-then-rename fallback or claim of power-loss durability. One bounded managed `.last-good` config remembers arbitrary installation paths if the primary is absent/corrupt. Each file is independently atomic, not a two-file transaction: the validated fallback publishes before the primary. Valid primary configs refresh that managed fallback at startup. One `.corrupt` input is preserved without rotation. Inputs at most64KiB are copied once; an oversized corrupt input is hard-linked rather than copied without a bound. An unsupported hard-link operation reports failure before primary replacement. Config/backup symlinks and directory targets reject. Actual canonical save/config paths must stay outside the preserved installation, including symlinked parent paths. Concurrent writers are outside this startup-only serialized owner contract.
