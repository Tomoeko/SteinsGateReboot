## Recomposition order

The first pass and combining reorder end at `0x14040c1bd`. Mode 2 then begins output again, preserves the actual input cursor, sets starter index zero and enables composition. It unconditionally copies one record with `0x1403f4930`, including after failed first publication. It walks the retained input count while the cursor is below that count and the sticky error is clear.

A candidate requires composition still enabled and the current record's supplied low-five-bit category in 10–12. If the starter is not the last output, the last output's modified combining class must be **strictly lower** than the current class. Class extraction uses the property low word's high byte only for categories 10–12, otherwise zero. An initial starter that is itself a mark is not replaced or reclassified before this check. Neutral mode 2 does not compose nonmark Hangul L/V/T records merely because the Unicode callback supports those ordered pairs.

The actual default wrapper `0x14040c5f0` clears the candidate output and rejects either zero input before invoking default Unicode callback `0x140417a40`. The already recovered original composition tables and Hangul callback gates supply the result; there is no inversion of decomposition data or host normalization. A successful callback result is then queried through the same genuine font's nominal callback. A missing candidate glyph rejects composition and keeps both input records. A different valid nominal glyph index is accepted exactly as returned.

Accepted composition copies the current input record first. If that copy sets the error, the native branch returns immediately before cluster merge, count reduction, property refresh or publication. Otherwise `0x1403a5f50` merges the output span from the starter through the just-copied record, output count decreases by one, and the starter's codepoint and entire `+0x0c` nominal word are replaced by the candidate and mapped glyph. Only the starter's low property word is refreshed through the recovered Unicode property callback; inherited upper state, mask and cluster remain except where merge explicitly changes them. Successful composition keeps the same starter and eligibility flag.

For a rejected or blocked mark, a preceding output class greater than the current class disables further composition in that run. Equality blocks the candidate without disabling the flag. The current record is copied; a resulting last output with class zero installs that output as the next starter and enables composition again. Sorting is capped at 32 records in the preceding pass, so the descending-class disable path remains observable in longer unsorted runs. Ordinary loop completion attempts publication even after a failed copy; the accepted-candidate error branch returns without that publication attempt.

## Output clusters and input-tail propagation

`0x1403a5f50` differs from the earlier input merge. Cluster level 2 immediately returns without changing clusters, masks or scratch flags. Levels 0 and 1 use the minimum unsigned cluster over the output span and expand equal-cluster boundaries backward to output zero and forward to output count. If the expanded span reaches the output tail, matching following input records starting at the current input cursor receive the minimum cluster. The comparison reloads the current output-tail cluster for every input record, preserving alias-sensitive behavior. Finally all expanded output records receive the minimum cluster; changed clusters clear mask flag `0x1`. The removed just-copied record participates in this merge before its count is dropped.

## Failure boundaries

The resident owner still preallocates both arrays with `MaximumLength + 1` initialized slots, with first-pass work bounded to 4096 live records and maximum length 4096. General allocation, growth, reallocation and heap failure remain outside this profile.

After failed first publication, the native unconditional recomposition copy may read an initialized **resident** slot beyond the live input count. This is preserved when the slot is inside resident capacity; it can overwrite the first logical input record while the sticky error remains set. Rejecting this copy just because the live cursor equals input count would change observed native failure state. If preparation succeeds with a cursor outside resident capacity, the native next instruction at `0x1403f4991` would read outside the owner. The portable operation reports `neutral recomposition copy exceeds resident input records after failed first publication` before that read and leaves the matching preparation state intact. This is explicitly unsupported invalid native continuation, not synthesized glyph output.

The earlier extra-selector error loop at `0x14040ce44` remains explicitly unsupported noncompletion. No error path silently publishes, consumes an invalid record or substitutes a fallback font.

## Separate final mapping

The original caller `0x1403f4440` invokes normalization, then `0x1403f4250`, a descriptor hook at `+0x48`, user feature-mask applications and optionally `0x14040d510`. Only after those phases does `0x1403f4616` read the current input count and pointer. Its loop at `0x1403f4630` copies each full four-byte word at record `+0x0c` to `GlyphIndex`; it does not clear or replace any other word. It then writes native buffer content tag 2 at `+0x58`, including for an empty buffer and after sticky normalization failure.

`PublishNominalGlyphIndices` performs that exact in-place record operation and returns strongly typed `NormalizedGlyphContent::GlyphIndices` with value 2. The encompassing content/lifecycle owner has not been invented or added to this resident owner's state. The future enclosing buffer must retain that returned tag at the recovered caller boundary. It must run the actual intervening fraction/feature/mark-class phases before final mapping. This API does not claim those phases, mirroring acceptance, dotted-circle policy, GDEF, complete glyph shaping or positions are recovered.

The borrowed `SfntFont` and immutable font-resource bytes must remain alive during normalization. Input properties must be prepared at the actual Unicode preprocessing phase and preserved through preceding phases; this method does not reclassify unchanged input or guess a Unicode version. After normalization `GlyphIndex` still carries codepoints and `+0x0c` carries nominal/variation glyph indices. After separate final mapping `GlyphIndex` carries those glyph indices; normalization cannot be reapplied to that representation as if it were Unicode input.
