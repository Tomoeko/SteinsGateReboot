# Motion mask shader selection

`SelectMotionMaskShaderProgram` recovers native pipeline phase 2 (`0x14054e210`) and texture-mask phases 3–5 (`0x14054def0`). Reference: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`.

Both selectors reuse the twelve original vertex-layout choices and matrix preparation. They publish their available vertex-color constant in **alpha/red/green/blue** order, unlike the ordinary and alternate selectors' red/green/blue/alpha order. `PrepareMotionMaskShaderColor` preserves that difference.

Phase 2 chooses pixel program `2072 + textureKind`, where absent/RGBA/alpha/luminance/red-green are kinds 0–4. Its scalar metadata is at `(textureKind + 12)*16` relative to that phase's metadata owner. Available scalar metadata receives the pipeline row's `+0x48` float word directly, without normalization or arithmetic. This establishes the native consumer for `MotionStencilControl::MaskRenderValue`; actual shader pixel semantics remain separate.

Phases 3, 4 and 5 choose pixel programs `2042 + (textureKind*2 + additionalVariant)*3 + phase-3`. Their metadata indexes `pixelIndex-2042`. Available metadata at relative index*16+0xc0 receives current-target reciprocal extents. The original graphics byte `+0x160` selects the additional variant. When enabled, the selector always publishes the two original float words at graphics `+0x164/+0x168` to relative index*16+0x2a0, without an availability test. The setter preserves the full original operation byte, while exact assembly `0x14054e09b/0x14054e0a1` uses TEST/SETNE to normalize it for program selection. Thus the bool input corresponds to `operation != 0`, including values above 1. Full geometric/pixel interpretation remains open.

The bounded unchanged-code oracle covers every layout, texture interpretation, mask phase and 0/1 variant: 1,152 cases / 3,456 repeated/cache-invalidated calls / 946,224 original instructions. Strict ASan/UBSan C++ comparison matches all 19,728 ordered program/binding/matrix/color/scalar/target/additional-payload events. Scalar and additional payloads include arbitrary float words, retained exactly. Trace SHA-256: `0b40bc4eea265f1ad72fd6d70e7dd7b1a3630eab3cceb01eb9874693701fd153`. Independent fixtures cover all scalar/texture-mask indices, metadata offsets, alpha-first colors and rejected phases/layouts/texture kinds.

GPU shader binding, commits and constant-buffer copying are observer boundaries. Texture-mask target creation, blend/depth/stencil coupling, reflection integration, Metal shader translation and native pixels remain separate acceptance work. Ordinary phases 0/1/6 stay in the existing ordinary/alternate selector modules.

Producer linkage: the actual command loop `0x140555610` calls renderer vtable `+0x40` → `0x14055ab20` → `0x1404c6100`. Command `+0x74` supplies the operation byte; mode-1 thresholds come from `+0x78/+0x7c`, while mode 2 uses `+0x78` and float32 `(1-minimum)-extent`. These are the existing [MotionMaskPlan Configure operations](motion_mask_plan.md). The original setter stores them unchanged at graphics `+0x160/+0x164/+0x168`.

A separate full-byte setter→selector oracle runs 1,152 cases / 3,456 calls / 969,789 original instructions and matches all 21,009 C++ program/cache/constant events. The exact setter also preserves every operation byte and threshold word before native boolean normalization. Trace SHA-256: `764850be8170be9d2cb98b4a2744f77af703a06758c355f579bdb98ec8f9abd4`.
