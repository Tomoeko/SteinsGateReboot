# Live graphics models during camera draws

Target: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. This extends the recovered camera operation in `layer_camera_draw.md`; it does not replace that note's native evidence.

The original camera operation pushes the global graphics model stack, composes its final live slot, draws actual children, then pops the slot. A copied model vector is useful for isolated recovery but cannot supply the graphics shader's live current model. The new `LayerCameraDrawScope` constructor borrows the actual stable `GraphicsModelStack`, which must outlive the scope. Current model and depth queries resolve that owner directly. Parent model changes before a draw are visible without rebuilding a snapshot.

Camera drawing computes the recovered parent/local product before pushing, then pushes the actual owner and writes the composed slot. Nested child tasks and shader consumers can observe that exact object. Existing scissor behavior is unchanged. Normal completion and child exceptions restore the model depth and prior parent slot. Empty stacks use the recovered identity push. Both the scope depth limit and actual owner's allocation limit remain enforced. Children must balance their own model operations; an unexpected final depth rejects without popping a foreign or absent parent. This is an authored safety rule; recovery of native misuse behavior is not claimed.

A first-party direct ASan/UBSan proof compiles ten actual source units and their recursive headers without a static archive or shared core. It replays the retained 1,000 unchanged-native camera cases, whose original witness executed 1,034,628 instructions, and compares the same matrix/scissor outputs while checking that the camera's model reference is the graphics owner's actual current slot. New tests exercise parent edits, real nested parallel child draws, child exceptions, empty stacks, capacity exhaustion, and an unbalanced child. The generated executable is retired after verification. This replay is a current implementation comparison against the retained native oracle; no new original game execution is claimed.

The frame projection, viewport, and scissor still come from the supplied containing frame state and physical scissor service. Connecting those to the selected target, root manager, graphics pre/post hooks, and live renderer remains separate work.
