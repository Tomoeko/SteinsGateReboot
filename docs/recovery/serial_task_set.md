# Owner-thread serial task sequence

Reference: `Files/STEINS.GATE.REBOOT/sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. MSerialTaskSet vtable `0x1405c14c8` selects update `0x1404c0420` and draw `0x1404c0200`.

The original updates the head while its DWORD status is Active (0). If it stays Active, traversal stops. Complete (1) removes it without calling its destructor; Retire (2) removes and destroys it. Later heads, including callback tail appends, can run in the same update. Head removal happens before retirement. Draw only visits the current head when its separate draw-pause byte is clear and its status is not Retire. Default construction sets auto-retire-empty byte `+0x1f`; an empty update sets the group's status to Retire. Append and Clear preserve that group status. Assembly checks status as a DWORD at `+0x18`, independently from draw pause at `+0x1c`.

The first-party queue owns linked `SerialTask` objects exclusively. A Complete task moves to an explicit external completion receiver without Close; the caller retains that unique owner and retires it at its actual external lifetime boundary. This C++ ownership transfer replaces the original raw-pointer relationship, rather than silently deleting a completed task or leaving it in the linked queue. Retire and Clear close linked owners exactly once. Generational handles expire on removal. A missing completion receiver is an authored safety rejection before unlinking. Callback state and borrowed services must outlive their task owners, including transferred owners.

A bounded original-instruction oracle covers 1,000 cases / 32,000 operations / 679,915 instructions. Native trace SHA-256: `42b5bdf32dd38d6607b75dd178eac2f939de59585faaa55146150c4468afb6dd`. The strict ASan/UBSan C++ comparison matches every ordered update/draw/destruction/tail-append event, group status and linked task/status/pause snapshot. Complete tasks remain separately owned prepared metadata in the original oracle. Actual append/prepend/clear/update/draw code executes; task callbacks are explicit observers. Native physical heap disposal, opaque task payloads and external completed-owner retirement are separate from this projection.

Five independent fixture groups cover Active head blocking, Complete transfer versus Retire destruction, full-DWORD draw arguments, paused-head behavior, same-update tail appends, completed owners surviving group destruction, persistent group status, stale/reused handles, bounded insertion, failure-completing Clear and missing-receiver rejection. Construction prepares bounded record/free-list storage. Owners are supplied during preparation; ordinary traversal performs no allocation except any caller callback work. Capacity and traversal work are limited to 65,536. Reentrant traversal, prepend during traversal, retirement mutation and closing a task from its own callback are explicit unsupported/safety domains.

This is the owner-thread path with native threaded-task byte `+0x1d` clear. Worker submission, queue synchronization, background cancellation/wait, RawTex image retention/publication, common Process integration and frame scheduling remain open. The original RawTex background method `0x1402929b0` creates a serial sequence containing a background call and a visibility continuation; that is the integration target, not an implemented claim here.
