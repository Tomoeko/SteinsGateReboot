# Script endpoint observations

`ScriptScheduler::ObserveWait` and `SquirrelVm::ObserveContext` are authored, read-only diagnostics of the actual portable owners. They copy the stored child, notification, timeout and stop predicates and the existing suspended frames, previous operation, next instruction and register scalars. A `Running` thread can still wait for a child or notification; status alone cannot identify its blocking owner. Object and context identities borrow their original owners. The result owns no `SquirrelValue`, canonical string, closure, buffer, or host root.

Both VM and Scheduler remain single-thread owners; these methods do not make concurrent access safe. Context copies require a live serialized owner-thread endpoint outside execution, collection, release and close phases. Invalid, foreign and stale identities reject. Copies cap frames at 32, registers per frame at 16, notification rows at 32 and each text field at 128 bytes, with explicit truncation flags. Frame selection keeps the most recent tail. These limits and copied source-line metadata are diagnostic policy, not recovered native timing or tracing. Stored notification matching, timeout expiry strictly below zero, child wake ordering and reader/compile/retirement gates are unchanged.

Five bounded independent fixture groups check suspended scalar copies and continuation, context bounds and nested frames, actual child waits, timeout/notification cancellation without retaining original strings, and typed pending/failed/raw-cache buffer states without consuming their real compile gate. A direct-source ASAN/UBSAN proof passed. This proves the authored observation contract, not whole original-script startup or native behavior.

The private original-script observer retains actual mounts, cache, worker, typed file Threads, Sound resources and finish registration. Its endpoint snapshot precedes their real shutdown, retains no extra VM roots, installs no trace callback and adds no scheduler visits. Prepared host services, physical extent inputs and bounded manual clock remain explicit. Sound completion latches diagnose configuration delivery; they do not establish decoded sample, voice, device, focus or audible readiness.

The frozen typed404 endpoint uses the current coherent APIs and preserves ordered real shutdown. Its actual main→init→sound child chain stops in loadSound after failed mounted delivery of `sound/bgm.psb.m`; GetLoading remains true and the completion latch false. All reader/mount tasks are empty. This identifies a persistent receiving failure, not missing worker opportunity. No startup rerun, forced completion or suffix alteration follows this diagnostic; actual archive/path lookup recovery is next. The prior full401 suites remain historical, while19 current targeted checks pass in each integrated/portable profile. Complete startup is open.
