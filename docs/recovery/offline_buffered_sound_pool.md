# Dynamic offline buffered source attachment

The real decoded pool can now feed a macOS manual offline sound graph while cue IDs, archive borrows, and physical source lifetimes remain distinct. The connector attaches an actual AVAudioSourceNode during source preparation and copies the recovered matrix into its callback owner before source commit. The containing `SoundResourceControl`, configuration/archive/cache references, reader worker, cue slot allocator, decoder, mixer, and schedule remain the recovered first-party owners. No script binding or native audio readiness is added.

The fidelity target is `sgre_steam.exe`, SHA-256 `75a83a0e2a7e22055417ae0474b47be98418c4e42c695c548b558705c404b9d8`. Read-only Binary Ninja uses `candidate:view:1:UEU`; all seven retained byte ranges match original PE offsets. Original instructions and analysis metadata are unchanged.

Native `381930` copies each selected channel's 16-byte resource value at `382583–38259e`, passes the requested count to `391bb0`, requests pause at `3825b5`, applies mix at `3825ce`, commits at `3825d6`, then increments/masks the ID at `3825e7–3825ef`. The separate native `playVoice` wrapper `38b700` initializes an omitted count to zero. The existing prepared C++ request default remains one; the containing Sound fixture explicitly supplies zero. `playVoice` stays unsupported until its full native options producer and service prerequisites are recovered.

Native `3921a0` supports pool0/1 slots, stops and flushes an existing source before `392580` destroys its voice and then callback, borrows actual format/data spans, allocates the 11-byte callback, and submits a buffer with null `pContext`. `380970` instead returns logical cue slots and releases archive borrows after callback retirement, retaining idle source storage. The authored node therefore borrows its actual decoded slot rather than an active cue ID. Its copied matrix and owned decoded samples survive logical cue/archive retirement; reuse closes and detaches the physical callback before releasing/replacing CPU buffer/callback storage.

Seven bounded original attachment cases execute 1,815 instructions at 283 PE-verified sites. They cover both pools, boundary slots, pause/no-pause, count zero/one/three/negative, NoSRC/rate combinations, old-source replacement, and failed source creation with null or opaque output. This witness starts at the initialized `381930` channel tail and ends immediately after the ID increment. Earlier cue selection/allocation and later lookup/publication are excluded. PSB accessor outputs, allocation, source voice/HRESULTs, matrix update, and commit are explicit independent ABI boundaries. They do not create an original audio device. The observed ignored native Submit HRESULT remains evidence, not a portable success policy. Full scalar coercion and service/mastering setup are pinned separate witnesses.

The macOS owner enables actual AVAudioEngine manual offline mode before mixer/output access. Caller format/rate are explicit; source rate must match and matrix frequency ratio must be unit or absent. Preparation allocates fixed bounded workspaces outside rendering. The real system callback consumes owned decoded interleaved frames, applies the recovered matrix, and writes the actual Float32 output planes without allocation, decoding, or I/O. Callback activity and remaining frames change only through actual consume/flush; native null context remains separate.

The connection is a serialized borrow. Source-owner close removes all physical callbacks before release; graph close disconnects physical callbacks without completing or flushing CPU samples. Weak callback state avoids cycles and cannot reach a released owner. Foreign callbacks fail before touching source state. Objective-C operations use the existing first-fault boundary, including source attachment; release stays nonthrowing. Partial attachment cleanup checks the actual node engine identity before detach, since allocation can precede failed attachment.

Eight direct-source ASan/UBSan groups exercise actual offline engine output and source/controller lifetime: independent two-source PCM/matrix output, cue/archive retirement with idle nodes, slot replacement/new IDs, global plus voice pause, stop/flush, partial malformed-channel failure, unsupported-pitch rollback, both owner release orders, actual containing Sound cache references, and foreign-thread/input rejection. The final graph has no hardware output. The first passing closure is retained before the narrow cleanup refinement; its unchanged result remains historical. All generated executables/objects are hash-retired.

This is an explicitly offline system producer. Native COM/XAudio2 service readiness, hardware output, device defaults, real clock/pump/focus, native callback timing, nonunit pitch/resampling, type2 continuous sources, full WMA/native decode fidelity, and complete `playVoice` registration remain open. The configured WMA options31 decoder profile is existing first-party decoder scope, not an OS/native WMA admission. No original game, script startup, visible window, or speaker output is involved.

The first frozen dynamic stage exposed its output protocol hooks publicly. After the original source owner closed, a caller could register a new raw borrow without the reciprocal source connection; its teardown could leave a dangling callback. That stage remains preserved and is blocked for publication. The corrected interface makes all output hooks private to the actual `BufferedSoundSources` friend and keeps derived hooks private. Public `ConnectOutput` publishes both sides; callers cannot bypass it through either type. Ten compile-time access checks and a ninth actual offline group verify reciprocal reattachment and replacement-owner destruction before an empty-graph render. Runtime bodies, native evidence, clocks and scheduling policies are unchanged.
